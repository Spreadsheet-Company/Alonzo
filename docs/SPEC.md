## 1. The unit: the cell

The cell is the basic unit of the engine, and there is nothing beneath it (*recommendation*, the owner's own statement of 2026-10-08, made the first rule of this page). A game fills a cell with a color and the host draws it as one pixel; the spreadsheet fills a cell with text and the host draws it as a box of glyphs. Both are the same cell seen through a different projection (`SD-23`): the **plane** projection reads a window of cells as one byte each, a color index, and the host blits the bytes; the **grid** projection reads the same window as lines of text, the view record of `KERNEL.4` (*shelf*: `conformance/README.md`, oracle 11), and the viewport draws them (`KERNEL.5`). Version 1 called the two the video modes of 1981, graphics and text, with the cell where the pixel and the character cell were (*exhibit*: the EGA drew 320 by 200 in sixteen colors and 80 by 25 characters from the same adapter; §14); version 2 reads them as two renderers of one model and not two modes (*recommendation*; decision 19): a sheet holds values, and its look is a declared map from a value to a style, the Palette sheet for the plane and the `look` rows for the grid (§3.1, §7.3), so that in either projection the value is the frame and the look is declared and never painted (`SD-32`), and a stacking game's lit blocks and its score in text share one sheet. The split of 1981 is what the consoles after it escaped with tile and sprite layers (*exhibit*: the Famicom of 1983, §14), and a page that copied it would have had to escape it too. A sprite is a range of cells. A level is a sheet. Physics is a formula: a position this frame is a formula of the position and the velocity in the last frame, and a collision is a comparison. A camera is two cells the host reads and places its window by (§3.8), so that a scrolling world costs a frame nothing. None of these is a device, and none needs one, which is why `CHARTER.md` §8 builds no asset pipeline, no sprite engine and no physics engine; every one of them is cells and formulas, in the language, where a stranger can read it, change it and optimize it (`CHARTER.md` §6, the hypothesis). The host's pixel is rented, as rule 3 rents the rasterizer: the engine never addresses a pixel, only a cell, and the host decides how many device pixels a cell gets (an integer, so that the image is crisp at the machine's pixel ratio, `KERNEL.3`'s check by eye).

## 2. The grid, the two buffers and the frame

**The grid.** A cartridge is loaded into one grid: `vla-lang`'s sheet model, sheets of cells, each cell a value (a number, a text, a truth value, an error value) or a formula, with defined names and a style table, as `frazaro build` builds one and `frazaro reflect` reads one (*shelf*: `core/src/sheet/mod.rs`, the model `vla-lang` takes with it, the Alonzo memory's move list). Coordinates are A1's: a column by letters, a row by number, both from 1. The Screen of a 320 by 200 cartridge is the range `A1:LH200` (*derived*: 320 = 12 × 26 + 8, the twelfth letter then the eighth).

**The two buffers, named.** A frame is a dependency graph over two buffers (`CHARTER.md` §4, the frame): a cell of this frame reads the previous frame anywhere, and this frame's cells wherever the reads are acyclic. This page gives the previous frame a name a formula can write, and it chooses the spreadsheet's own spelling over a new function (*recommendation*; decision 2 in §11). **Every sheet `X` of a loaded grid has a twin named `X.last`, holding every cell of `X` as it was when the previous step finished.** A twin holds values only, never a formula; it is read-only to the program and to the host; the engine makes it at load and fills it at the end of every step. A formula reads the previous frame by an ordinary cross-sheet reference, `Screen.last!B2`, and reads this frame by an ordinary reference, `Screen!B2` or `B2`. Nothing new is added to the language: a `.last` sheet is a sheet, the reference is a reference, the dependency graph is the graph recalculation already builds, and a reference into a `.last` sheet adds no edge to it, since the twin's values are fixed before the step begins. The suffix needs no quotes in a formula, since Excel quotes a sheet name only for a character outside letters, digits, `_` and `.`, a leading digit, or a name shaped like a reference (*shelf*: `core/src/refers.rs`, `sheet_needs_quotes`, the owner's pass of 2026-10-04). A cartridge may not name a sheet ending in `.last`, and a sheet's name is at most 26 characters so that its twin fits Excel's 31 (*exhibit*, §14).

Why a sheet and not a function. Excel's own way to read a previous value is iterative calculation over a circular reference, which the Life-in-Excel tradition uses (*exhibit*: Microsoft's "Change formula recalculation, iteration, or precision", §14); it reads the previous iteration's value in the order of Excel's calculation chain, so what a cycle computes depends on that order, and a cell that wants this iteration's neighbor and that one's previous value cannot say which it means. A function such as `LAST(B2)` would say it, but it is a new mechanism in the evaluator, a word no spreadsheet knows, and a thing nobody can look at. A twin sheet is a thing anyone can look at: `view` shows it, the viewport can show the previous frame beside this one, `reflect` of a saved cartridge lists it, and the owner's rule that an ambiguous reading gets explicit words is kept by the suffix itself (*shelf*: the Frazaro memory, "name the choice"). The cost is a copy of the sheet's values at the end of each step: 64,000 cells of eight bytes is 512 KB, under a tenth of a millisecond at memory speed, against the two million evaluations a second the frame already pays (*derived*; the implementation may swap buffers instead of copying, which this page does not see).

**The acyclic rule.** Within a frame, the references that read this frame form a directed graph over the grid's formula cells, and that graph must be acyclic; a cycle is refused by name, naming the cells that close it, at load for the cartridge's formulas and at a `write` that adds one, never during a step (*recommendation*; the refusal is recalculation's own, `KERNEL.7`'s, and the treaty's recalculation will refuse it the same way). A cell that reads itself through its twin, `=Screen.last!B2+1`, is not a cycle; a cell that reads itself directly is. The synchronous automaton (every read of the last frame) and the scan-order rule (every read of this frame in one order) are both special cases, as the charter says, and both are written in the one notation: Life reads `Screen.last` alone; sand reads the row beneath in `Board` and the rows above in `Board.last`.

**The theorem.** Each frame is a total function: the graph is finite and acyclic, and every function of the subset returns a value or an error value and never diverges (§4.4), so every step terminates by construction, and the cartridge is a productive stream transformer, inputs in and frames out, never stuck. That is why a replay is a proof (§6, §7.6). The frame is Lustre's synchronous instant, the twin its `pre`, the acyclic rule its causality check and the first-frame `IF` over `Clock!B1` its initialization arrow (*math exists*: Caspi, Pilaud, Halbwachs and Plaice 1987, §14; the reading is `docs/ALGEBRA.md` §2.2).

**The step.** One step computes one frame: the engine writes the Clock's frame cell (§3.5); every formula cell of every sheet that is not a twin is recomputed, in a topological order of the graph above, reading twins for the previous frame and the grid for this one (*math exists*: Sestoft 2014, as the charter cites it); a value cell keeps the value it holds, whether the cartridge put it there or a `write` did; a step computes values and never formulas, so the formula cells after a step are the formula cells before it, cell for cell, the rule `AD-7` (§9; decision 22), held by a test (§13); and when every formula has a value, every sheet's values are copied into its twin, and the step is done. A step takes a budget in cells and may stop before it is done, reporting how far it got, and be called again until it is; the host draws the last complete frame from the twins meanwhile, so the grid never freezes (`SD-34`). Between two steps the grid holds the last complete frame, and the twins hold the same values until the next step changes them; a `write` between steps changes the grid and not the twins, which is what gives a button its rising edge: during the next step `Input!B5` is the new press and `Input.last!B5` is the last frame's. A cartridge's own writes between steps are the Write sheet's (§3.9), values the host carries from one frame's effects into the next frame's grid, so that a state can be a value that costs nothing to keep.

The graph's depth is the frame's critical path and its width is the parallelism on offer; a shared formula over a range is one shape evaluated once per cell, which `KERNEL.20` vectorizes; both are the charter's claims and this page changes nothing in them (*shelf*). Nothing on this page asks the evaluator for a mechanism it would not have for a spreadsheet; the frame is recalculation with a budget, a snapshot and a clock cell (*recommendation*, the page's central claim, marked *engineering*).

**What a rule costs** (*noted 2026-10-11*, `CART.2`'s scoping, decision 2; *measurement*, Sand's rule profiled over `vla-lang` 0.9.0, every frame held to a sand written by hand; `REARVIEW.md` has the numbers). The language's step computes only the cells a change reaches, in runs of one shape's cells evaluated together, so how a formula is written decides what a frame costs. ## 3. The device sheets, cell by cell

Alonzo is Varvara to VLA's uxn: where Varvara maps its devices into uxn's memory at fixed ports, sixteen bytes each, with a vector per device that the machine evaluates on an event (*exhibit*: the Varvara page, §14), Alonzo maps its devices into the grid as sheets with fixed layouts, and has no vectors, since the frame is the only event and every input is a cell written before the step. The nearer precedent is TIC-80, whose devices are memory-mapped registers a program peeks and pokes, the screen at address zero, the palette at `0x3FC0`, the gamepads, mouse and keyboard at `0xFF80` (*exhibit*, §14): a device sheet is a register file with names instead of addresses and a formula bar instead of `peek`. The layout follows the spreadsheet's own convention for a block of settings, a label in column A and its value in column B, so that a person reading the sheet in the viewport sees `up | 1` and not a bare `1`, and follows ICAEW's tenth principle, inputs, workings and outputs separate and clearly identified (*exhibit*, §14): the Input sheet is inputs, a cartridge's own sheets are workings, and Screen, Audio and File are outputs.

Two directions, told apart by the sheet. An **input** cell is written by the host before a step and read by the cartridge's formulas: the Input sheet, and the Clock. An **effect** cell is written by the cartridge's formulas and read by the host after a step: the Screen, the Audio voices, the File's save, the Keys, the Camera and the Write sheet, and since version 5 the Commands sheet. A device sheet's host-written cells hold values and never formulas (a formula there is refused at load, since the host would overwrite it every frame and nobody would see why); the cartridge is free to put formulas into effect cells, and that is how a game sounds and draws. Cells of a device sheet outside its layout are refused at load, so that a later version of this page can add a row without colliding with a cartridge that used it (*recommendation*). Every name below is compared as the model compares sheet names, without case (*shelf*: `Workbook::find_sheet`).

### 3.1 Screen

The framebuffer (`CHARTER.md` §3). Its size and mode are declared by the cartridge's manifest (§7.2), `(screen plane 320 200)` or `(screen grid 80 50)`, the width then the height: the size of the window the host draws, `A1` its top-left when the cartridge has no Camera sheet, the row number the y and the column index the x, both from 1. Without a Camera sheet a cell outside the declared size is refused at load, as version 1 refused it; with one (§3.8) the Screen may be any extent within §10's limits and the Camera places the window, so that a tower taller than the window or a world wider than it is a sheet and not a trick (*recommendation*; decision 21).

- **Plane mode** (`ENGINE.2`, the games). Each cell holds a color index, a whole number from 0 to one less than the Palette's row count. The plane projection (§4.5) reads the Screen's window as one byte per cell in row-major order: the cell's value when it is a whole number from 0 to 254, and 255 for anything else, an empty cell excepted, which reads as 0, and a formula before its first value, which reads as 0 too (*corrected 2026-10-09*, `ENGINE.1`'s second slice: the language's plane reads it so, `vla-lang/src/machine/plane.rs`, and the fake module already did). The host paints a byte below the Palette's count with that row's color and any other byte in the error color, magenta `#FF00FF`, so that a formula that produced text, an error value or an index past the palette is seen and never silently black (*recommendation*; the convention is the one game engines use for a missing texture). The record of the same window (the grid projection) shows the same cells as values, which is `ENGINE.2`'s equality test.
- **Grid mode** (`KERNEL.5`, the spreadsheet and the text games). Each cell holds what a spreadsheet cell holds, and the viewport draws the window as it draws any sheet: the text, the number formats and the fills the record declares, and the `look` rows of §7.3, a declared map from a value to a style index, so that a cell whose value changes changes its fill through a style the cartridge declared and never through a formula that paints (`SD-32` kept whole: the map is declared, the value is the frame; version 1's sentence that a fill cannot change per frame is withdrawn, decision 19). A roguelike, a text adventure and Frazaro itself are this mode. The first game needs no cartridge at all: the spreadsheet is a grid of this kind at a frame rate of one, and `frazaro view` already prints it. (*Corrected 2026-10-12*, `ENGINE.8`'s first slice, as the host and the viewport draw it.)
  - The host views the record of the Screen through the Camera's window, at a load for frame 0 and after each step, and its own viewport draws it; each frame's record replaces the last with the person's scroll and selection kept.
  - A formula with a value shows its value, aligned by its kind, and keeps its text for the bar. A formula before its first value shows its text, so a grid cartridge at rate zero shows its formulas' texts until the first edit, unless its rows carry `value` rows, a save's spelling.
  - A look matches a cell's value: a number by its value, so `7` and `7.0` are one and so are `0` and `-0`, which the language spells apart in a `cell` row and a `value` row; a text by its characters exactly; a truth value; an error by its name. Of two looks a value matches, the first the record holds is its look. An empty cell, and a formula with no value, match no look: the plane reads an empty cell as 0 and the grid draws it empty, the two renderers' one difference.
  - A row's height is in points, at 96 dots an inch, so 15 points is the default row of 20 pixels; a hidden row, like a hidden column, draws nothing.
  - The record spells a number by Rust's `{}`, which writes no exponent, so `1e300` is 301 digits, drawn right-aligned and clipped; Excel's General format is the first game's to want. (*Corrected 2026-10-14*, `ENGINE.14`: clipped from the left, a right-aligned number lost its leading digits, so that Buffet's `Dice!F3`, 1,073,741,912 in a 64-pixel column, read ")73741912". A number or a date under the `general` format whose text, with the padding on both sides, is wider than its column now draws as many `#` as fit, as Excel fills a cell under a fixed number format, in a `wrap` cell too; its value is the record's, unchanged. Excel's General format would first round it or write an exponent; the viewport never respells a value.)
  - A number under a format whose number format is a code of Excel's, `(format 27 none "0.00" nowrap)`, draws the text the record's `text` row holds for it after its `cell` or `value` row (Frazaro's `KERNEL.47`): aligned and matched to a look by its value, as under General, and as many `#` as fit when the text is wider than its column; a text under a code's fourth section draws its `text` row too, on the left. The viewport keeps the code and never applies one, and gives the bar the value as the record spells it. (*Corrected 2026-10-18*, `CART.12`, decision 10: until then the viewport counted a code's `format` row malformed and the `text` row unknown, and drew the value.)
  - The host views the sheet a viewport shows, and only it (*noted 2026-10-14*, `ENGINE.14`): a tab clicked is answered, the sheet viewed and shown, and while it shows, each frame and each scroll that leaves its region view it through the region the viewport shows, never the sheet whole, which for Sand's Stay is 34 MB and 1.4 s natively where a full screen of it is 33 ms; the Screen's tab gives the Camera's window back, scrolled to its corner as at a load.
  - Every sheet drawn is the values record after frame 0 and the grid record at frame 0, as the Screen is (*corrected 2026-10-15*, `ENGINE.18`, decision 38; for every cartridge, since it changes no value): the sheet a viewport shows in the Screen's place and a page's viewer of the sheets alike. `ENGINE.17` already skipped a still sheet's load and paint, and the view is what remained. *Measurement*, the 0.1.3 module in Node 24.21's V8, through the owner's full screen of default cells, 40 columns by 68 rows: a sheet of 1,000 formulas reading the day viewed in 2.0 to 2.2 ms from the grid record and 0.34 to 0.36 from the values record; Buffet's own sheets in 0.02 to 0.14 and 0.01 to 0.05.
  - A cartridge's views on its own sheets (*version 4*, `ENGINE.18`, decisions 37 and 41; a cartridge that says `(spec 4)` alone). Its Screen may be hidden, `(sheet "Screen" hidden)`, a row version 3 already reads: the tab strip keeps it behind its box of hidden sheets, and nothing views it until it is shown. The cartridge opens on the sheet its Camera's third row names at the load (§3.8), a value or a formula's `value` row, else on the first visible sheet of its tab order, the cartridge's own; so a cartridge whose views are sheets opens on its first view with no Camera at all, and a save opens where its game stood. The manifest's `(screen grid w h)` keeps its words, the mode and the window a Screen shown is drawn through, so an ending can be the Screen a game shows. A grid cartridge with no Screen loads too, and nothing views it; a Camera that names it is said once.

The Screen has no layers and no sprite port in this version, and its scroll is the Camera sheet (§3.8): a scrolling world is a sheet larger than the window and two cells the host reads, which costs a frame nothing, where an offset every Screen formula read through `INDEX` would cost the window's every cell a lookup a frame, the whole of §10's budget on scrolling alone (*derived*; `docs/ALGEBRA.md` §3). A layer is a second sheet composited by a formula; a sprite is a range (§1); the composite as a projection, a Sprites sheet of ranges at positions drawn in order with blank transparent, is named for version 3 (§12).

### 3.5 Clock

Three cells, and no wall clock anywhere (`AD-4`: Frazaro has no clock, Alonzo is the clock; `CHARTER.md` §4, rule 4: `NOW` is the Clock device and `RAND` is a seeded cell). Column A the label, column B the value.

| row | A | B | written by |
|---|---|---|---|
| 1 | `frame` | the frame number: 0 after load, then `n` during and after the `n`th step | the engine, as the first act of every step, and nothing else: a person's write is refused |
| 2 | `rate` | the cartridge's frames per second, the manifest's `(rate ...)`; 0 for a cartridge stepped by edits (§5) | the engine, at load; a person, 0 or a whole number from 1 to 120, which the host reads after each step and steps at |
| 3 | `seed` | the dice: the manifest's `(seed ...)`, or the number the host chose when the manifest says `(seed host)`, a whole number from 1 to 2147483646, so that a Park and Miller cell seeded from it never sticks at 0 | the engine, at load; the host's one write, at load, of a number from the browser's random source, recorded by the replay; a person, a whole number in the same range |

The frame number is the only clock (`ROADMAP.md`, `SPEC.1`). Elapsed time is `=Clock!B1/Clock!B2`, a formula the cartridge writes if it wants seconds; at rate 0 it is `#DIV/0!`, honestly, since no seconds pass, and the frame number counts edits (decision 20). Random numbers are a formula over the seed and the last frame's state, in the open: Park and Miller's minimal standard, `=IF(Clock!B1=1, Clock!B3, MOD(State.last!B1*16807, 2147483647))` in a cell of the cartridge's own sheet, `State!B1` here, the seed its first value, is exact in doubles, since 16807 times 2^31 is under 2^53, and is published ground (*math exists*: Park and Miller 1988, §14; *derived* for the exactness; *corrected 2026-10-10*, `ENGINE.3`: the example had the cell in the Clock's fourth row, `Clock!B4`, which the Clock's layout, `A1:B3`, refuses at load, measured; in a cartridge's own sheet it was exact at all of 40 frames). The engine supplies no random function, and a cartridge naming Excel's volatile functions, `NOW`, `TODAY`, `RAND` or `RANDBETWEEN`, is refused at load by name with the Clock sheet named in the refusal, since a cell that reads the wall clock is a cell no replay can reproduce (*recommendation*; decision 7).

(*Corrected 2026-10-10*, `ENGINE.3`'s first slice, as the engine and the host now answer; measured before, every value landed in all three cells. A person's `cell` row into the Clock is held cell by cell, `cart-write-clock`: the frame refused, since the step writes it first and would undo the write unseen; the rate held to 0 or a whole number from 1 to 120; the seed to a whole number from 1 to 2147483646. A formula and a derived row are refused there already, as cells the host writes. The rate is §9's teacher: the host reads it after each step with the other effects and steps at it, a rate of 0 stepping on edits from there and a rate from 0 ticking again with nothing owed, so the grid and the loop never disagree. The seed the host chooses under `(seed host)` comes from the browser's random source, `crypto.getRandomValues`, and is written once, after the load and before frame 0 is drawn: no time, so §6's second rule holds without its exception.)

(*Version 6*, `CART.12`, decision 59; a cartridge that settles, `(settle K)`, alone.) The frame number counts acts. The engine writes `B1` as the first act of a step that begins an act, the load's first step among them, one more than the last it wrote, and leaves it at a settle step (§5), so that a time shown or a die thrown off the frame number moves once an act, as rate 0's frame counts edits, and never holds a settle open: a write before a frame keeps a settle going (§5), and a settle step that numbered its frame would be one at every step. The step's answer still numbers the machine's frames, as the replay and a window's changes do (§4.4, §7.6), so for such a cartridge `B1` is the acts and the step's frame is every step. A save resumes the machine at `B1`, the acts, and the count goes on from there. A person's write of a rate above 0 is refused, `cart-write-clock`, since such a cartridge settles at rate 0 alone (§7.2).

### 3.6 Audio

Four voices, each the Web Audio graph's own oscillator and gain and nothing else (`ENGINE.4`; `CHARTER.md` §8: no synthesizer of its own). A table, not a label column, since a voice is a row: row 1 the headers, rows 2 to 5 the voices.

| row | A `voice` | B `wave` | C `note` | D `volume` |
|---|---|---|---|---|
| 2 | 1 | `square`, `triangle`, `sawtooth` or `sine`, the OscillatorNode's own words | a MIDI note number, 69 being A4 at 440 Hz, a fraction allowed for a slide | 0 to 1, the gain; 0 is silence |
| 3 | 2 | | | |
| 4 | 3 | | | |
| 5 | 4 | | | |

The cells hold for one frame: after each step the host reads the four rows and renders each voice's state for the frame's duration, `1/rate` seconds, scheduled against the audio clock with a lookahead and never against the animation clock, which is the lesson of "A Tale of Two Clocks" (*exhibit*, §14). A tick is `volume` 1 for one frame and 0 after, 33 ms at 30 frames a second; a tone is a `note` held over frames; a fanfare is a formula over `Clock!B1`. The frequency is `440 * 2^((note - 69) / 12)`, computed by the host, so that a cartridge thinks in notes as a tracker does and the sheet reads as music. Noise, envelopes and samples are not in this version (§12); Varvara's audio device carries an ADSR and samples (*exhibit*), and a later version may add columns, since a table grows to the right.

(*Corrected 2026-10-10*, `ENGINE.4`'s first slice, as the host now sounds the sheet; every figure a *measurement* of that day under headless Chrome 154, in `REARVIEW.md`.)
- **The timeline.** A frame sounds where the last frame's sound ends: the last frame's time and `1/rate`, the rate the host read after that frame. While the loop keeps up, the frames lie end to end on the audio clock, so a rhythm in the cells is a rhythm in the sound, whatever the display's interval. A frame's time stays between the audio clock's now and 100 ms ahead of it, twice a lookahead of 50 ms:
  - a frame whose time has passed starts the timeline again 50 ms ahead, so a cartridge too heavy for its rate sounds its frames as they come, each voice holding until the next;
  - a frame further ahead than 100 ms is not sounded, and the timeline stays where it was, so a burst after a stall sounds its first frames and skips the rest, as its screen shows only its last;
  - at rate 0 every step sounds 50 ms ahead and holds until the next (§5).
- **The voices.** Each voice is one `OscillatorNode` and one `GainNode`, the voices' gains into one shared gain into the destination, and nothing else: the host computes no sample (`CHARTER.md` §8, held on the shim by `tools/check_web_offline.ps1`).
  - A voice's gain is its volume over four, so four voices at full volume never clip: four squares at gain 1 peak at 3.81, at a quarter at 0.953.
  - The frequency is set at the frame's time, the oscillator keeping its phase, so a slide is a staircase at the frame rate, as a chip's registers are written once a frame.
  - Every change of a voice's gain approaches its value through the graph's own `setTargetAtTime`, with a time constant of 3 ms: a gain set at once steps 17 to 24 times a smooth wave's own largest step, and the approach at most 1.33 times, down to 55 Hz.
  - A wave cannot be scheduled: an oscillator's type takes effect when the JavaScript runs. So a wave changed is a new oscillator started as the old one stops, at one time on the audio clock; while the voice sounds, through a dip, the gain approaching 0 from the frame's time and the switch five time constants, 15 ms, later.
  - Only what changed is scheduled, so a voice that holds costs no event.
- **A voice that is no voice.** The volume is read first, an empty cell being 0, and a volume of 0 is a rest, whatever the rest of the row holds. Above it the wave is one of the four words, compared without case, and the note a number from 0 to 127, MIDI's range, a fraction allowed, every one below the Nyquist frequency of every sample rate from 25 kHz. Anything else in any of the three, a text, a truth value, an error value or a number out of range, silences the voice for the frame, and the host says so once for each cell and each value shown, as it says a Camera cell (§3.8): a notice, the sheet never refused.
- **When it sounds.** Only after a person's act, the page's Sound on, which makes the audio context, since a context a page makes before a gesture stays suspended (the browser's autoplay policy, §14); and only while the loop runs. A pause, a hidden page, the end of a replay, a refused step and an unload each cancel every voice's later events and approach 0 from the audio clock's now; a start sounds the frame the grid holds at once.

### 3.8 Camera

The window's place, as two cells (*recommendation*; decision 21): column A the label, column B the value. An effect: the cartridge's formulas write it and the host reads it after each step, and the window it draws for the next frame is the Screen's declared width and height placed at that row and column, passed as the view call's window argument (§4.5), so that the engine knows no camera, the view call takes no new argument, and a scrolling world costs a frame nothing. It is PICO-8's `camera()`, the offset applied at the draw and not per pixel (*exhibit*, §14), where an offset read by every Screen formula would cost the window's every cell a lookup a frame (§3.1). Optional: a cartridge without a Camera sheet draws `A1` to its declared size, as version 1 did. A window past the Screen's extent reads blank, which the plane paints as color 0 and the grid as empty cells; a value that is not a whole number from 1 reads as 1 and the host says so in its status line (`SD-30`), since the Camera is read after a step and never refused. In grid mode the Camera is the viewport's scroll when the sheet exists; the first game, the spreadsheet, has none, and its scroll stays the host's own state (`SD-23`). (*Corrected 2026-10-12*, `ENGINE.8`: at a load the viewport scrolls to the window's top-left, and when the Camera moves it scrolls by the Camera's move, so that the person's place inside the window is kept and the window moves under it; between moves the scroll is the person's.)

| row | A | B |
|---|---|---|
| 1 | `row` | the window's top row, a whole number from 1 |
| 2 | `column` | the window's left column, a whole number from 1 |
| 3 | `sheet` | *version 4's*: the sheet the game shows, a sheet's name, or empty for none |

(*Version 4*, `ENGINE.18`, decisions 37 and 40; a cartridge that says `(spec 4)` alone.) The third row is the sheet the game shows. At the load it names the sheet the cartridge opens on (§3.1), a value or a formula's `value` row. After each step, when its value changes from the frame before and names a sheet the grid holds, compared without case as the model compares names, the host shows that sheet at the frame's end as a tab clicked is shown: the Screen through the Camera's window as its tab gives it back, any other sheet through the region the viewport shows. Between its changes the person's tabs win, as the person's scroll wins between the Camera's moves. Empty, or a formula before its first value, names no sheet and moves nothing; a name the grid does not hold, a number, an error or a truth value is said once, as the other two cells are, and moves nothing. The row and the column stay the Screen's window's place and never scroll another sheet. In plane mode the plane draws the Screen, and a sheet the Camera names is said once. ### 3.9 Write

The grid writes the grid, in values (*recommendation*; decision 18; the argument is `docs/ALGEBRA.md` §2.3). A table: row 1 the headers, and a row a write, column A the sheet, column B the address or range, column C the value; a row whose column B is empty is no write. An effect: after each step the host reads the rows and, before the next step's inputs (§5), issues each as its own `write` of one `(derived "<sheet>" "<addr or range>" <value>)` row, so that a value a formula computed lands in another cell as a value, and a refused row is refused by the record's own status 1, with its id and words, while the rest still apply (*corrected 2026-10-08*, `ENGINE.1`, decision 3 of its scoping, found by writing the fake module: version 2 had the host issue these as `cell` rows, which the module cannot tell from a person's edit, and a person's `cell` row may replace a formula where a derived write may not; the `derived` row is the write call's input alone, never a cartridge's row, and the ABI number stays 1, no signature having changed its meaning). Version 1 had one way to keep a state, a formula of the shape `=IF(event, new, Me.last!B5)`, a frame axiom written by hand for every such cell and re-evaluated every frame to conclude that nothing happened, which is the frame problem by its own name (*exhibit*: McCarthy and Hayes 1969, §14); the law of inertia, a value persists unless something writes it, is what the `write` call already gives the host, and this sheet gives it to the cartridge. State is then values that cost nothing to keep, and events are writes: the stacking game's tower is seven values written on a freeze and holds no formula however tall (Appendix B).

| row | A `sheet` | B `address` | C `value` |
|---|---|---|---|
| 2 | a sheet's name | an address or a range; empty for no write | a number, a text, `true` or `false` |
| 3 and on | | | |

The rules. A derived write may target a value cell of any sheet that is not a twin, a host-written cell excepted, and nothing else: a formula cell (the step computes values and never formulas, §2), a twin, a host-written device cell (the Input sheet, the Clock, the File's first two rows) or a cell outside the model's limits is refused by name, `cart-write-derived`, printed by the host as a sentence (`SD-30`), and the remaining rows still apply; the refusal is a function of the frame, so a replay reproduces it. A range fills every cell of the range with the value. Derived writes are applied before the frame's own writes, so a person's edit or the host's Input row wins over a derived write to the same cell. A replay does not log them, since they are re-derived (§7.6). They cost what any effect costs, a formula a row evaluated every frame, so a cartridge keeps its Write sheet short. What is not proposed, and why: a `(formula ...)` row written from a cell would be the program writing code at run time, which the owner's veto of `GENSYM` carries by its own words, "runtime-arbitrary-code-execution is the same wall's other, more obvious breach" (*shelf*: `Frazaro/docs/BETA_ROADMAP.md`, the `GENSYM` entry), and which would make every static property of this page a per-frame property (§9); the first draft of this sheet carried formula rows and was narrowed the same hour (`docs/ALGEBRA.md` §2.3).

(*Noted 2026-10-12*, `CART.4`, the stacking game Kairos, the Write sheet's second client after the input card.) A row's address may be a range, and every cell of it takes the value: a stop writes its run of lights into the tower as one range, `"K3:K5"`, and a game's end clears the tower as another, so the tower holds no formula however many games are played. A derived write lands before the next frame's step, a frame after the formula that asked for it, so a picture that must not show the gap draws the frame's own state over the cells being written; Kairos's Gate draws the stopped row through the beat after a stop. The kit's verb `put` writes a row, its target, its address while a test holds and its value (`cartridges/common.vla`).

### 3.10 Commands

*Version 5's* (`ENGINE.25`, decisions 48 to 52; a cartridge that says `(spec 5)` alone). The cartridge's own commands, as a sheet, so that a cartridge declares its acts as data, a page lists them beside its own and runs one by its name or by a key, and a person reads them, rewords them and moves their keys by editing a cell (§9). An effect: the cartridge writes it, a formula may write any of its cells, and the host reads it at the load and after each step with the other effects. A table: row 1 the headers, and rows 2 to 101 a command each, so a hundred at most (§10).

| row | A `name` | B `words` | C `holds` | D `key` |
|---|---|---|---|---|
| 2 | the command's name: lowercase letters, digits and hyphens, as a cartridge's name is, each name once on the sheet | what it does, a sentence a page shows beside the name; a formula may make it live | whether it holds now: empty, `TRUE`, a number other than 0, or a formula before its first value holds; `FALSE` or 0 holds not | its key, a `KeyboardEvent.code` as the Keys sheet spells one (§3.4), or empty for none |
| 3 to 101 | | | | |

A row whose A is empty or holds the empty text is no command, as a Write row whose B is empty is no write. The engine refuses at load a value of column A from row 2 that is no command's name, and a name written twice, by name, `cart-command-invalid`, naming the cells (§4.7); a formula in A is the host's to judge after each step, and a row it cannot take, a name badly spelled or written twice, a `holds` that is a text or an error, or a `key` that is no text, is said once (`SD-30`) and is no command, or has no key, until it changes.

What a command does is the game's. A command run is written into the Input sheet's twentieth row before the next step, for that step alone (§3.3), and the game's formulas read it. Commands run one a frame, in the order they were run, sixteen waiting at most; a seventeenth is said and dropped. While the loop is paused at a rate, a command waits for the next frame; at rate 0 each command steps the grid once, as an edit does (§5). A command that holds not is run by nothing: a page lists it nowhere, a key bound to it passes on to the game's buttons and the viewport as if unbound, and a run of it otherwise is said and not queued. `holds` is read after each step, so a formula of the sheet shown, `=Input!$B$19="Market"`, reaches a person's tab a frame later, as a Keys sheet's binding by formula does. While a replay plays, a command is refused, as a person's edit is, and the replay's own rows play.

The key. While its command holds, the host takes it on the Screen's place, the plane's canvas or the grid's viewport, when no Ctrl, Cmd or Alt is held, and runs the command; a held key's repeat is taken and runs nothing. A page hears a key before the host does and may bind it otherwise, so a person's keymap goes over a cartridge's key. A code that is both a Keys button's and a command's key is the command's while it holds, and two commands holding with one key are the first row's; each is said once. A digit of the keypad, while Num Lock is on so that its `KeyboardEvent.key` is the digit, runs the command whose key is the digit row's, `Numpad7` the one of `Digit7`, unless a command holding names the keypad's own code: the keypad is how a spreadsheet's person enters numbers, and the page's keymap reads a digit so (*amended 2026-10-19*, `CART.14`'s hand test). Num Lock off, its arrows, Home and End stay the viewport's; the Input sheet's last key keeps the keypad's own code (§3.3); and a Keys button bound to a digit row's key is held by that key alone. (*Corrected 2026-10-18*, `CART.12`, decision 64: at rate 0 the host took no command's key on the grid's viewport, where every key was the viewport's, though this section says the host takes one on the Screen's place. It takes a holding command's key on the viewport at rate 0 as at a rate, before the viewport sees it, whatever sheet shows, as a Keys binding is the game's whatever sheet shows; every other key stays the viewport's.) (*Amended 2026-10-20*, `SPEC.5`, decision 69: on a grid a command's key holds on the game's sheets alone where the manifest names any, and never on a work or a read-only sheet that is not the game's, whatever its `holds`. At rate 0 no formula can scope a key to a sheet: the host writes `Input!B19` with an act's rows alone, so a tab clicked moves no `holds` until the next act; the manifest's sheets say it at once (§7.2).)

A page names a cartridge's command by the cartridge's name and the command's joined by a dot, `buffet.buy-1`, a spelling no page command and no person's own takes, so that a person's keymap holds each game's commands apart (*the page's*, `web/README.md`).

### 3.11 The reserved names, and what a new device is

Reserved: `Screen`, `Palette`, `Input`, `Keys`, `Clock`, `Audio`, `File`, `Camera`, `Write`, and every name ending in `.last`, all compared without case; and, for a cartridge written to version 5, `Commands` (§3.10), a name that a cartridge written to 1 to 4 may give a sheet of its own. A cartridge's other sheets are its own, including the `Frazaro` sheet a program compiled from English carries (§7.4), which no rule reads. A new device, in a later version of this page, is a sheet with a layout in this section, a direction (input or effect), a row in the host's duties (§8.3) and, only if it cannot be served by a read or a write through the module's exports, an import named in §8.2 and added to the allowlist; the layout comes first and the code after, the order the charter sets for every brick. The candidates this page can already name are the gamepad (an input, filling columns B to E of Input from the Gamepad API, no new sheet), a key matrix (an input, a sheet of codes held), a MIDI port (an input and an effect through the Web MIDI API where the browser has it, a local device and not the network; §12), the patch as a sheet (§12), the composite as a projection (§12, version 3's), and threads (a device of the host's that changes no cell, `CHARTER.md` §4: a device after a measurement).

## 4. The four calls

The engine's whole contract is four calls into `vla-lang`: load a cartridge, write cells, step, view (`CHARTER.md` §4). This section gives each its inputs, its answer and its refusals, in the shape of `frazaro-core`'s C surface, since that shape exists, is tested and is what a page already reads (*shelf*: `core/src/abi.rs`, `web/index.template.html`). The calls are Rust functions of the `vla-lang` crate, which the `alonzo` crate calls directly, and C exports of the engine's module, which the host shim calls; the memory pair and the record are the same on both.

### 4.1 The handle

A loaded grid is kept in the module's memory between calls and named by a **handle**, a whole number from 1 the `load` call returns and every other call takes first; 0 is never a handle, a handle is never reused within one instance of the module, and a call with a handle that is not live is refused by name. This amends CALLOSUM §7 decision 1 for the engine's door, "no model handle in the module's memory", on the measurement that decision asked for (*shelf*): the view record of a 10,000-line program prints in 812 to 893 ms natively (*measurement*, `CHARTER.md` §7), and a frame of 64,000 cells thirty times a second cannot rebuild its grid from text, so the escape hatch the decision named is taken here and nowhere else; Frazaro's own doors keep the pure function. The handle is explicit rather than an implicit single grid (decision 3): it costs one argument, it lets a page hold a game and its replay, or an editor's grid and the running copy, in one instance, and it is how every C surface names an open thing (*exhibit*: a file descriptor; the Component Model's resources are `i32` handles into a per-instance table, §14).

### 4.2 `load`

In: the cartridge's bytes (§7), and a name for the file, used only in refusals, as `frazaro_reflect` takes one (*shelf*). Out: a status-0 record whose text is one row, `(cartridge <handle> "<title>" plane|grid <width> <height> <rate>)`, which is what the host needs to size its canvas and set its timestep. What it does, in order: refuses a file holding a `defmacro` or an `include` as a cartridge's source, before its manifest, at the line of the first (`cart-source-unexpanded`), since the pass expands a source and the load never does (§7.8; decision 31); reads the manifest form and refuses a defect by name (`cart-manifest-invalid`, the distro reader's twin, naming what is wrong); checks the spec version it names against this page's; loads the rows that follow into a fresh grid, as the inverse of what `reflect` prints (§7.3), refusing a row it cannot hold with the row's line in the record's `line` field, and refusing a cell the rows write twice, `cart-cell-written-twice`, naming both lines (decision 23), a `value` row after a `formula` row being the formula's last value and never a second write; makes every sheet's `.last` twin; checks each device sheet against §3 (a Screen cell outside the declared size when there is no Camera sheet, a Palette out of order, a formula in a host-written cell, a cell outside a layout, a volatile function anywhere, a reserved name misused), refusing by name; builds the dependency graph and refuses a cycle by name; writes the Clock's three cells and the File's two; fills the twins with the grid's values; and answers. (*Corrected 2026-10-09*, `ENGINE.1`'s second slice, the order as the engine keeps it over the language's two calls: the Clock's and the File's cells, and the Input sheet with its eighteen labels and zeros when the cartridge holds none, are made in the grid after the device checks and before the graph reads them, so that the host's eighteen rows always land, a write making no sheet; a later `(spec ...)` is refused before any other defect of the manifest, its directives being a later page's; and a load whose rows hold a whole number above 0 in `Clock!B1` is a save's, which resumes at that frame.) Nothing is computed: the frame number is 0 and every formula waits for the first step. Every version 1 cartridge is a version 2 cartridge: `(spec 1)` loads under this page, the one new refusal, a cell written twice, naming a defect version 1 left undefined. And every version 1 and 2 cartridge is a version 3 cartridge, since version 3 adds no row and no directive: its changes are above the rows, in the source and the pass (§7.8), and the one new refusal names a source handed to the load (decision 32). (*Version 4*, `ENGINE.18`, decision 36.) `(spec 4)` is read, and its two rows, the Input sheet's nineteenth and the Camera's third, lie inside their layouts for a `(spec 4)` cartridge alone. The engine makes such a cartridge's Input sheet of nineteen rows, the nineteenth's B empty until the host names the sheet shown, and `describe` prints its extents as `A1:E19` and `A1:B3`. A cartridge written to 1 to 3 keeps version 3's layouts, its Input sheet of eighteen rows and its extents, refused version 4's cells where version 3 refused them; so every version 1 to 3 cartridge is a version 4 cartridge, its `describe` byte for byte the same. (*Version 5*, `ENGINE.25`, decision 53.) `(spec 5)` is read, and its sheet and its row, the Commands sheet and the Input sheet's twentieth, are a `(spec 5)` cartridge's alone: the engine holds the Commands sheet to its layout, `A1:D101`, and its names to §3.10's rule, refusing `cart-command-invalid`; makes such a cartridge's Input sheet of twenty rows, the twentieth's B empty until the host names a command; and `describe` prints `(device "Input" "A1:E20" input)` and `(device "Commands" "A1:D101" effect)`. For a cartridge written to 1 to 4 a sheet named Commands is its own, loaded, checked and described as any sheet of its, and its Input sheet keeps its eighteen or nineteen rows; so every version 1 to 4 cartridge is a version 5 cartridge, its `describe` byte for byte the same. (*Version 6*, `CART.12`, decision 66.) `(spec 6)` is read, and its directive, `(settle K)`, is a `(spec 6)` cartridge's alone, at rate 0 alone (§7.2). Version 6 adds no sheet and no row: its Input sheet is version 5's twenty rows, and its `describe` prints `(settle K)` among the manifest's directives. So every version 1 to 5 cartridge is a version 6 cartridge, its `describe` byte for byte the same.

### 4.3 `write`

In: the handle, and rows in the one notation, `(cell "<sheet>" "<addr or range>" <value>)` or `(formula "<sheet>" "<addr or range>" "<text>")`, one a line, as the cartridge spells them (§7.3) and as the record prints them, or, from the host's derived writes alone, `(derived "<sheet>" "<addr or range>" <value>)`, held to §3.9's rules. Out: `(written <n>)`, the cells changed. A write that refuses a row changes nothing, so the host issues each person's edit and each derived row as its own `write` (*corrected 2026-10-08*, `ENGINE.1`): a refused row then refuses itself and not the frame's inputs, and a replay's rows give the same frames however its writes are grouped. Every input is a cell the host writes and every edit is a cell too (`CHARTER.md` §4): the host's eighteen Input rows before a step and a person's edit of a Board in a cartridge's editor arrive by this one call, told apart by the sheet they touch and nothing else. A write takes effect at once in the grid and not in the twins (§2). Refused by name: a sheet the grid does not hold, naming the ones it does (the `view-sheet-unknown` shape); a `.last` sheet, which is read-only; a Screen cell outside the declared size when there is no Camera sheet; a formula into a host-written device cell; a row that is not a `cell`, `formula` or `derived` row; a formula that would close a cycle, naming it. A range fills every cell of the range with the value, or with the formula moved as Excel moves a filled formula (*shelf*: `Sheet::set_formula`, the shared formula), which is how an editor clears a board in one row. (*Corrected 2026-10-09*, `ENGINE.1`'s second slice, as the language and the engine answer: rows apply in order, and a refused row undoes the rows before it; a value may be an error, `(error "#N/A")`; a write makes no sheet; a cell outside a device sheet's layout is refused at a write as at a load; and the engine's checks run over every row before the language's, so that a write refused by both names the engine's refusal, the only order that keeps a write atomic. *Corrected 2026-10-10*, `ENGINE.3`'s first slice: a `cell` row into the Clock is held to the Clock's cells, the frame refused and the rate and the seed to their ranges, `cart-write-clock` (§3.5).)

### 4.4 `step`

In: the handle, and a budget, the most cells to evaluate in this call, 0 meaning no limit. Out: `(step <frame> <evaluated> <of> done)` or `(step <frame> <evaluated> <of> yielded)`: the frame number being computed, the cells evaluated so far in this frame, the frame's total, and whether the frame is complete. A step that yields holds the frame in progress; the next `step` call continues it, and a `write` between a yield and the completion is refused by name, so that a frame is a function of the inputs it began with (*recommendation*). The budget is in cells and never in milliseconds, so that the frame's values are the same whatever the host's chunking and the step reports work rather than time, the house's rule for every engine (*shelf*: the Frazaro memory, budgets in work, not seconds); the host turns its time slice into cells by measuring how many the last call did per millisecond, which is its business (§5). Refusals: a handle not live; an evaluator refusal `KERNEL.7` defines, such as a function this version does not compute, named, which is raised at load and not here. An error value in a cell, `#DIV/0!`, `#VALUE!`, `#REF!`, `#NAME?`, `#N/A`, `#NUM!`, is a value and propagates as Excel propagates it; it never refuses a step, and on the Screen it is a magenta cell (§3.1). A step never changes a formula (§2, `AD-7`): the formula cells after it are the formula cells before it, cell for cell, which `vla-lang`'s test holds on every fixture (§13).

(*Version 6*, `CART.12`, decision 60; a cartridge that settles alone.) A done frame's answer gains a word for where the settle stands after it (§5): `(step <frame> <evaluated> <of> done settling)` while the rule holds, the host then stepping again with no act; `(step <frame> <evaluated> <of> done unsettled)` when the rule still holds and K settle steps have followed the act, so that the grid stops settling, waits for the next act and the host says so (`SD-30`); and `(step <frame> <evaluated> <of> done)` once the grid has settled. A yielded frame's answer is unchanged, and so is every answer of a cartridge that does not settle. The engine keeps the settle's state, so that the native players and the page's host step a settle alike, and a step after a `settling` answer is a settle step whoever calls it.

### 4.5 `view`

In: the handle, a projection's name, a sheet's name and a window (`A1:F20`; empty for the sheet's whole extent), the last two as `frazaro view` takes them (*shelf*: oracle 11); the window is where the Camera is honored, the host passing the Camera's row and column as the window's top-left and the declared size as its extent (§3.8), so that the engine knows no camera and the call takes no new argument. Out, for the projection `grid`: the view record, the lines the door prints, byte for byte the same spelling, with one row this page asks `KERNEL.7` to add to oracle 11 the day values exist: after each `(formula ...)` row, a `(value "<sheet>" "<addr>" <value>)` row holding the formula's computed value, spelled as a `cell` row's value is, absent before the first step; and two rows this page asks `KERNEL.4` to add to oracle 11 whether or not values exist, `(look "<sheet>" <value> <index>)`, the look map of §7.3, printed after the `format` rows, and `(row "<sheet>" <n> <height|none> shown|hidden)`, the twin of the `column` row, so that a grid cartridge can declare a tall cell (decision 19). Out, for the projection `plane`: the bytes of §3.1, one per cell of the window in row-major order, in the record's text, the one record beside a build's whose text is not UTF-8 (*shelf*: `frazaro_build_xlsx`). The `.last` sheets are viewable by name, and the record's `(sheet ...)` rows list them after the cartridge's own sheets as `hidden`, the reader's own word for a sheet without a tab (*shelf*: `reflect::Visibility`), so that a viewport shows the cartridge's tabs and can show the previous frame on request. Refusals: the view's own two, a sheet unknown and a window that is not a range (*shelf*), and a projection this version does not have, naming the two it has. The plane is a projection of `vla-lang`'s, a pure function of the model and a window whose output can be a golden, and so the language's by `AD-4`; it is the second implementation of the projections seam, which `KERNEL.12` wanted a contributor to write to prove the seam takes additions (*shelf*: `BETA_ROADMAP.md`, `KERNEL.12`; `core/src/kernel.rs`, `Projection`). (*Corrected 2026-10-09*, `ENGINE.1`'s second slice: the plane is selected by name in the view call beside the `Projection` trait, whose output is lines, and is not its second implementation; whether rasters get a seam of their own waits for a second one, `KERNEL.12` still open, in the language's own words, `vla-lang/src/machine/plane.rs`.) (*Corrected 2026-10-14*, `REPO.4`, the pin at `vla-lang` 0.9.3: the language answers a third projection, `values`, the `grid` record less its `formula` rows, every other row as the record prints it, each formula's `value` row among them (Frazaro's `KERNEL.37`), so that a host drawing a grid every frame moves no formula's text. The engine passes a projection's name to the language as it stands, so the module answers `values` and its refusal of a projection names the three. The host and its double draw and answer `plane` and `grid` until `ENGINE.8`'s second slice, which draws the grid from `values`; the engine's own test holds a window's `values` to its `grid` record without the `formula` rows.) (*Corrected 2026-10-14*, `ENGINE.8`'s second slice: the host draws a grid cartridge's Screen from `values` at every frame after the first, and from `grid` at frame 0, a load computing nothing, so that the formulas show as their texts until their first values; its double answers `values`.) (*Corrected 2026-10-15*, the pin at `vla-lang` 0.9.4, `ENGINE.19`'s scoping: the language answers a fourth projection, `changes` (Frazaro's `KERNEL.42`). Its answer is a header, `(changes "<sheet>" "<range>" <since> <at> <n>)`, then the rows of each cell whose `values` rows the last complete frame changed, in row-major order, exactly as `values` prints them, and `(empty "<sheet>" "<addr>")` for a cell with no rows. Where the language cannot say which cells changed, the header ends `whole` in place of `<n>`: before the first frame since a load, a resumed grid's included; at a frame that changed more cells than the machine keeps room for; after a write that changed a formula or added a cell, until and at the next frame's end; and while a value written since the last frame lies in the window. A change is judged by the values' spelling. The host's rule: holding the window's `values` record at frame `<since>`, replace each named cell's rows with the given ones, and the result is the record at `<at>`, byte for byte. The engine passes a projection's name to the language as it stands, so the module answers `changes` and its refusal of a projection names the four. The host and its double draw from and answer the three until `ENGINE.19` is built.) (*Noted 2026-10-15*, `ENGINE.19` built: the host asks for a window's `changes` before its view, §5's steps 5 and 6, and the double answers them from its last two frames' twins, with room for every change, its refusal naming the four.) (*Corrected 2026-10-17*, the pin at `vla-lang` 0.10.0: a `format` row's number format may be a code of Excel's, `(format 2 none "0.00" nowrap)`, and the view record prints, after a cell's value, the text the number draws under its code, `(text "<sheet>" "<addr>" "<text>")`, where the formats hold a code; a record whose formats hold none prints none, byte for byte as before, and a load skips the row (Frazaro's `KERNEL.47`). The engine passes the record through as it stands. The viewport counts the row as unknown and draws the value, so a code is not yet drawn.) (*Corrected 2026-10-18*, `CART.12`, decision 10: the viewport reads a code and draws a cell's `text` row in its value's place, §3.1. A `text` row is a cell's row in a window's changes, laid by the host with the cell's others.)

### 4.6 The record, the memory pair, and the calls beside the four

Every answer is one record in `abi.rs`'s shape: four little-endian `u32`, the status, a line, the id's length and the text's length, then the id's bytes and the text's bytes; status 0 is an answer and the text is the output; status 1 is a refusal, the id the catalog's, the text its words, the line the cartridge row it stands on or 0; status 2 an input that is not UTF-8, named (*shelf*). The host allocates every input with the module's allocator, passes a pointer and a length, and frees inputs and records alike with the length each was allocated with. Beside the four calls the module exports what a page needs and nothing more: the allocator pair; the ABI version, a number that is this page's version and stays while an export is added and no signature changes its meaning, the discipline `frazaro_abi_version` keeps (*shelf*); the crate's version as text (*corrected 2026-10-09*, `ENGINE.1`'s second slice: the engine's and the language's, `alonzo 0.1.0 (vla-lang 0.8.0)`, so that a page names both); `describe`, the manifest as read, one directive a row, then one `(device "<sheet>" ...)` row per device sheet with its layout's extent and direction, then one `(budget <rate> <formula-cells> <a-second> <line>)` row, the cartridge's formula cells after the fills, their product with the rate, and the charter's line of two million a second, so that a page prints what it loaded, a stranger sees the devices without this page, and a cartridge over the console's line says so before it runs slowly (§10, decision 24; *corrected 2026-10-11*, `CART.2`, decision 16: before it may run slowly, since the line counts every formula cell every frame and the step computes only the cells a change reaches, so Sand's 126,449 formula cells at 30 frames a second are 3.8 million a second by the line, and its worst stretch steps at about 60 frames a second in the browser; the host's sentence says "may"; and *corrected 2026-10-12*, the pin at `vla-lang` 0.9.2, Frazaro's `KERNEL.30`, laid here: then the machine's census, the plan printed as rows so that what a cartridge costs a frame is read before a frame runs, a `(plan (shapes n) (texts n) (formulas n) (levels n) (runs n) (lanes n) (alone n) (every-frame n) (cycles n))` row, a `(readers "<sheet>" n)` row for each sheet a change to which is followed, and a `(shape k "<sheet>" "<first cell>" "=<R1C1>" (cells n) (levels ...) (runs ...) (alone n) (reads ...))` row for each shape in the plan's order, with `(calls ...)`, `(missing ...)`, `(sheets n)`, `(same k)` and `(every-frame why)` where they hold, each read named by the path the machine takes, `slot`, `array`, `lookup`, `cells`, `once`, `start` or `each`; computed when asked, a load and a step keeping nothing for it; and *corrected 2026-10-14*, the pin at 0.9.3, Frazaro's `KERNEL.35`: a sheet of 16 readers or more, which the machine keeps by the rows or the columns a changed cell must stand on to reach them, prints `(readers "<sheet>" n (most k))`, the most readers one changed cell of it meets, as Kairos's `State`, `State.last` and `Levels` do); `unload`, which frees a handle; and, since version 3, `expand`, the pass of §7.8, a source and the texts it includes in and the cartridge's text out, so that the page builds what it loads by the same function as the command line, as an act of its own that no load calls (decision 26; built 2026-10-10, `SPEC.3`'s second slice: the texts it includes come in one buffer, each path then its text, a NUL between each and the next, as Frazaro's translate takes its phrasebooks (*shelf*); it takes no handle and touches no grid; and a host asks for it when a person builds and not when it attaches the module, so that a module without it, the page's double, still drives the loop and declines a build in words; `tools/check_host_exports.ps1` holds the twelve names). ## 5. The frame's order of operations

The loop is the host's and only the host's (`AD-4`), in JavaScript, in `web/`, hand-written and read in review (`AD-5`). Its shape is the fixed timestep with an accumulator, the standard the industry settled in Fiedler's "Fix Your Timestep!" (*exhibit*, §14), with two changes a sheet allows: there is no interpolation, since a frame has no sub-frame state to interpolate, and the loop never skips a step to catch up, since the frame number is the clock and a skipped frame would be a frame that never existed.

1. **The tick.** The browser calls the host's animation-frame callback with a timestamp (*exhibit*: `requestAnimationFrame`'s `DOMHighResTimeStamp`). The host adds the elapsed wall time to an accumulator, after capping it at a quarter of a second so that a stalled tab does not ask for a hundred frames at once, Fiedler's cap against the spiral of death (*exhibit*). (*Corrected 2026-10-10*, `ENGINE.3`, found by the owner's hand test: the host held the accumulator itself to the same quarter second, against a backlog of slow steps, so a rate under four frames a second, whose interval is longer, was never owed a frame, and the teacher's rate of 1 froze the loop, the edit that would have raised it again waiting for a frame that never began. The backlog is held to the larger of a quarter of a second and one frame's interval, and a rate that moves starts it again with nothing owed.) (*Corrected 2026-10-12*, `CART.2`'s playtest pass, *measurement* in headless Chrome: a tick's time is put on the grid of the frame's interval when it lies within a quarter of a millisecond of it. The grid's step is the frame's interval over the whole number of display intervals it spans, or the frame's own interval where it is shorter. The display's timestamps jitter by a tenth of a millisecond. With the accumulator's remainder at its threshold, a tick a few hundredths of a millisecond early owed no frame and the next owed two, so Sand at a rate of 60 presented 38 to 40 of its 60 frames a second, and a frame at 30 came 50 ms after the last now and then, against 33.3. On the grid, a rate of 60 presents one frame each tick of a 60 Hz display, and 30 one each second tick. A display whose interval is off the grid by more is timed as its ticks come. The loop oracle's `pace` case holds it.) While the accumulator holds at least one frame's interval, `1/rate`, the host runs one frame (steps 2 to 6) and subtracts the interval; a host that cannot keep up runs late, never ahead, and never skips (*recommendation*). When the page is hidden the host stops ticking and resets the accumulator on return (*exhibit*: the Page Visibility API; background tabs are throttled), so a game in a background tab is paused, not fast-forwarded.
2. **The derived writes.** The host issues the Write sheet's rows it read after the last step (§3.9), each as its own `write` of one `derived` row (*corrected 2026-10-08*, `ENGINE.1`), before the inputs, so that a person's edit or an Input row wins over a derived write to the same cell; a refused row is printed as a sentence and the rest apply; a replay re-derives them and logs none.
3. **The inputs.** The host writes the Input sheet's eighteen rows for the frame, from the state of the keys it holds (set by `keydown` and `keyup` on `code`, mapped through the Keys sheet it last read), the pointer's place in Screen cells, the buttons, the wheel's notches and the last key, as one `write` of rows; a person's edit, from a cartridge's editor, follows as its own `write`, so that a refused edit refuses itself and not the frame's inputs, and a replay issues its rows the same way, all before the step (*corrected 2026-10-08*, `ENGINE.1`; version 2 had the edits in the inputs' call). (*Corrected 2026-10-10*, `ENGINE.3`'s second slice: a replay issues each frame's rows as one `write` after the derived writes, its Input rows and a person's edits together in their order; a write applies its rows in order and every row a replay logs had landed, so the one write lands as the live writes did, §7.6.) (*Version 4*, `ENGINE.18`: a `(spec 4)` cartridge's rows are nineteen, the sheet shown the last, §3.3.) (*Version 5*, `ENGINE.25`: a `(spec 5)` cartridge's rows are twenty, the command that runs at the step the last, §3.3, one command a frame from those waiting, §3.10.) (*Corrected 2026-10-15*, `ENGINE.19`: the host writes only the Input rows that differ from the rows it last wrote, in their order, and none when none does; all of them at the first frame since a load and after a person's edit of the Input sheet, a replay's rows or a refused write, each of which forgets the rows last written, as the recorder forgets its record of the sheet at the same acts. The sheet holds what the rows say either way, so every replay keeps its bytes. *Measurement*, the scoping, in V8: the 48 rows of version 3 written in 51.5 µs a frame, two of them in 4.1.) (*Noted 2026-10-16*, `ENGINE.7`: a rebuilt cartridge applied to the running game, §7.8, is a person's act among the edits, in the order the acts were made: its changed rows one write, all or none, after the Input rows, so that the frame's derived writes land before them live as in a replay. At rate zero it is one edit and one step.)
4. **The step.** The host calls `step` with a budget of cells. It sets the budget from the last call's cells per millisecond and the time it means to spend, a fraction of the display's interval that leaves room for the draw (*corrected 2026-10-12*, `CART.2`'s decision 20: three quarters of it, where the host held a half. A step of *s* ms is presented at 1,000 × *f* ⁄ *s* frames a second, capped at the cartridge's rate, where *f* is the share; Sand's water steps its heaviest seconds in 22.6 to 24.9 ms in the browser, presented at 20 to 22 frames a second at a half and at 30 at three quarters. The loop oracle's `slice` case holds the share); if the step yields, the host draws the last complete frame from the twins and continues the step on the next tick, reporting the progress as a sentence in its status line (`SD-34`: `frame 42, 31,000 of 64,000 cells`), so that a cartridge too heavy for the machine runs slowly in plain sight rather than freezing the page.
5. **The effects.** When the step is done the host reads, through `view`: the Screen as the plane (plane mode) or as the record (grid mode); the Palette's sixteen rows; the Audio's four rows; the File's `save` cell; the Keys sheet, whose changes rebind the keys for the next frame; the Camera's two cells, which place the next frame's window; and the Write sheet's rows, which become the next frame's derived writes; and the Clock's rate, which a person's write may have moved and the loop then steps at (*corrected 2026-10-10*, `ENGINE.3`; §3.5). (*Version 4*, `ENGINE.18`: for a `(spec 4)` cartridge the Camera's third row too, whose change shows the sheet it names, §3.8.) (*Version 5*, `ENGINE.25`: for a `(spec 5)` cartridge the Commands sheet too, its names, words, holds and keys the commands of the frames until the next read, §3.10.) (*Corrected 2026-10-15*, `ENGINE.19`: each device sheet is read by its changes over its extent, §4.5. The host keeps a sheet's cells as last read, with their frame, and asks for the sheet's changes first: whole, or another frame than the one after the cells', and the sheet is read whole as before; the cells' own frame, or no cell named since it, and the cells are kept; cells named since it, and each one's value is replaced, an empty cell's address removed. Each device's reading runs over the cells as before, so the Write sheet's rows still become every frame's derived writes. Frames 0 and 1 are read whole, the language answering whole before and at the first frame.) A view the host holds over the module's memory is made fresh for each read and never kept, since the memory's buffer is detached by any growth of the module's memory (*exhibit*: MDN, `Memory.grow`, §14).
6. **The draw and the sound.** Plane mode: the host writes the bytes through the Palette into an `ImageData` of the window's size and draws it onto the visible canvas scaled by a whole number of device pixels per cell with image smoothing off, the one way a 2D context stays crisp (*exhibit*: `imageSmoothingEnabled`, §14); `KERNEL.3` decided the canvas (`CHARTER.md` §7, *measurement*), and a WebGL texture of indices with the palette in a fragment shader is the escape hatch, taken only when a measurement on `CART.1` names the blit as the bottleneck (rule 3's spirit). Grid mode: the viewport draws the record (`KERNEL.5`). (*Corrected 2026-10-12*, `ENGINE.8`'s first slice: the host's own viewport, over an element the page hands it, draws the record step 5 read, the window's through the frame's own Camera, every frame's replacing the last with the person's scroll and selection kept (§3.1, §3.8). *Measurement*, the scoping, Chrome 154 headless: an 80 by 50 window of formulas views in 9 to 10 ms and is read and drawn in about 5, against a step of 0.3; the formulas' texts are nearly all of the view, so a second slice draws from a record without them, asked of the language.) (*Corrected 2026-10-14*, `ENGINE.8`'s second slice: every frame after the first is drawn from the `values` projection (§4.5). *Measurement*, the owner's `?blit=1` in Chrome 155 in fullscreen: the grid card's 80 by 50 window drawn again at a p50 of 5.2 ms and a p95 of 6.1, the view 1.1 of it and the viewport's load and draw 3.1, against a bar of 8.3.) (*Corrected 2026-10-15*, `ENGINE.17`: a frame whose record of the Screen, or of a sheet shown in its place, is byte for byte the one the host last loaded into the viewport, the viewport still holding the model it made of it, is neither read nor painted, a still frame; the view still runs, its text being what tells, and the viewport paints a person's scroll and selection itself. A load, a tab clicked and `redraw()` always draw. *Measurement*, headless Chrome 155 at the owner's full screen, over the loop oracle's still card, whose Screen changes once in 30 frames: the main thread's work a frame from 2.8 to 3.3 ms to 0.8 to 1.0, and a frame's p50 from 2.4 to 2.6 ms to 0.5 to 0.6.) (*Corrected 2026-10-15*, `ENGINE.18`: a sheet shown in the Screen's place is drawn from the values record after frame 0, as the Screen is, so that a still sheet's frame keeps only that cheaper view, §3.1; and a frame whose Camera names a new sheet draws that sheet, the frame's own draw and never a still frame, §3.8.) (*Corrected 2026-10-15*, `ENGINE.19`: a frame's own draw of the Screen, or of a sheet in its place, and a page's refresh that passes still, ask the window's changes before its view, §4.5, while the viewport holds the values record the host noted for that sheet, its model unpatched by anyone else. Cells named since that record's frame are laid on the held text, by cell, and on the viewport's model in place (`patch`), a draw that views nothing; none named is a still frame that views nothing; whole, another window or another frame views as before. A load, a tab, a scroll and `redraw()` always view. The viewport still paints whole; `ENGINE.20` paints the named cells alone. *Measurement*, headless Chrome 155 at the owner's full screen: a still frame's main-thread work a frame from 0.79 to 0.83 ms to 0.49 to 0.56 over the loop oracle's still card, and from 0.56 to 0.61 to 0.42 to 0.46 over Buffet's Stocks; its module calls in V8 from 226 µs to 13, and from 107 to 14 or 15.) (*Corrected 2026-10-15*, `ENGINE.20`: the viewport paints a patch by its cells alone wherever its canvas holds the full paint of the model patched, unscrolled and unresized since, and the cells named are no more than a quarter of the cells in view. Each named cell's band of its row, with the span its text spills over and the span of a text on its left that spills into it, before the patch and after, is painted again by the full paint's own steps under the band's clip, and the rest of the canvas is kept. A line in an opaque color is filled as a rectangle one device pixel wide, so that every rasterizer paints a repaint's lines as it paints the full paint's. *Measurement*, headless Chrome 155 on the GPU at the owner's full screen: Buffet's market day, a patch of about three cells of Stocks, from 1.3 to 1.7 ms of main thread, one run 2.3, to 0.6 to 0.8; the loop oracle's `changes` card, about eight cells patched at every frame, from 1.3 ms to 0.6 to 0.7.) Sound: each voice's oscillator and gain are set for the frame's audio time, a lookahead ahead of the audio clock (*exhibit*, §14). (*Corrected 2026-10-10*, `ENGINE.4`: the sound is scheduled after the Clock's rate is read, so that a rate a frame writes times that frame's sound; the frame's time is §3.6's timeline, and only the voices that changed are scheduled.) A `save` edge hands the person the file (§7.5).

Pipelining, the draw of one frame beside the step of the next, is the host's (`CHARTER.md` §4) and needs a worker and an `OffscreenCanvas`, which changes nothing on this page; it is taken when a measurement wants it (`ENGINE.1`). Every call into the module is synchronous and one at a time; the engine is never re-entered.

**Rate zero** (*recommendation*; decision 20). A cartridge whose manifest says `(rate 0)` has no tick and no accumulator: the host steps once after each `write` made on a person's act, an edit, so that the frame number is the count of edits, the replay is the undo history, and `SD-22`'s source apart from the changes is the cartridge apart from its replay. The Input sheet is not written (§3.3), there being no frame to hold a button in, but for a `(spec 5)` cartridge's twentieth row, written before every step, a command stepping the grid once as an edit does (*version 5*, `ENGINE.25`, §3.10); the derived writes of step 2 still apply before the next edit's step and never trigger a step of their own, so a Write row that is never empty cannot step the grid forever; the effects are read and drawn after each step as at any rate, and a voice's state holds until the next step, since `1/rate` is undefined (*noted 2026-10-10*, `ENGINE.4`: each step sounds 50 ms ahead of the audio clock, §3.6). Version 1's slogan, a spreadsheet as a game whose frame rate is one, was a figure; the first game is a cartridge at rate zero with no special case in the host, and `frazaro view` already prints its frames.

**The settle** (*version 6*, `CART.12`, decisions 57 to 61; a cartridge that says `(settle K)` alone, at rate 0). An act settles. After an act's step the grid steps again, with no act, while the last frame changed a formula cell's value or had a write before it, at most K steps after the act's; then it waits for the next act. That is the language's fixed point (Frazaro's `KERNEL.48`, `vla-lang`'s `Machine::changed`): a frame that changed no formula's value, with no write before it, is followed by frames that change nothing, the twins at its end being the twins it read. So the act's own frame never ends a settle, its end copying the act's writes into the twins, where a formula reading one sees it a frame later; and a click on a cartridge that reads the press (§3.3) is three frames, the act's, the one after its release, and one that proves nothing moved, which computes nothing (*derived*; *measurement*, `CART.12`'s scoping: 0.26 to 0.28 ms natively on a board of 262,144 squares, and an idle frame's 7 µs the third). Excel's iterative calculation is this, its maximum iterations K and its maximum change zero (*exhibit*, §14). The count is every formula cell's, no sheet left out. What a settle step writes is nothing but two things. Before the first settle step the engine releases the act's one-frame rows, the press, `Input!B13` to `B15` written 0, and the command, `B20` written empty, the place (`B11`, `B12`, `B19`) kept (§3.3); a release that changes nothing is no write. And the Write sheet's derived rows apply before every settle step as before every step (step 2), each a write, so a cartridge whose Write rows never empty settles for K steps and is said to. The Clock stands while an act settles (§3.5). The engine keeps the rule and the state and answers each done frame's place in it (§4.4); the host loops (`AD-4`): while the answer says `settling` it steps again inside the tick's slice, a step at a time with the derived writes before each, drawing each frame as any frame is drawn, a frame whose window did not change being still, and the effects read after each; a person's act made meanwhile waits for the settle to end, in the order the acts were made; and an `unsettled` answer is said, the grid then waiting for the next act. The load settles too: the host steps the load's act, frame 1, with its rows and no other write, and its settle, so a settling cartridge opens on computed values where a grid at rate 0 had shown its formulas' texts until the first edit (§3.1). A rate written above 0 is refused for such a cartridge (§3.5), so a settle never meets a tick. *Measurement*, the scoping, natively, a board of 512 by 512 in 797,189 formula cells: the load's settle two frames, 224 ms; an act's settle at 15% three frames at the median and 25 at the most over 200 acts; the deepest cascade 1,315 frames, at 9%, the percolation threshold's; K for that board 4,096.

## 6. Determinism

The rules, each a sentence, so that a replay is a proof and a floor is a number (*recommendation* throughout; the owner's standing brief for every engine, determinism first, *shelf*: the Frazaro memory):

1. **A fixed timestep.** The cartridge declares its rate; a frame is one step; the host never runs a partial frame and never skips one. Wall time decides only when steps happen, never what they compute. At rate 0 there is no timestep: a frame is one edit, and the host steps once for each write made on a person's act (§5). (*Version 6*, `CART.12`: a settling cartridge's act is its step and its settle's steps, each a function of the act and the grid, the engine's state making a step a settle step wherever it is called, §5.)
2. **The frame number is the only clock.** `Clock!B1`, written by the engine; `NOW` and `TODAY` are refused; the host writes no time into any cell, ever. (*Corrected 2026-10-10*, `ENGINE.3`: the sentence ended "except the seed at load when the manifest asks for it"; the seed the host writes then is the browser's random number and no time, §3.5, so the exception is gone.)
3. **A seeded cell is the only dice.** `Clock!B3`, from the manifest or from the host once at load, recorded by the replay; `RAND` and `RANDBETWEEN` are refused; a random number is a formula of the seed and the last frame (§3.5).
4. **The input log is the only nondeterminism.** The grid after step `n` is a function of the cartridge's bytes, the seed and the rows a person or the host's Input wrote before each of the `n` steps, and of nothing else; the host's derived writes (§3.9) are a function of those and add nothing. This is Doom's demo contract, a record of every tic's inputs from which the game replays bit for bit, with the generator's state synchronized (*exhibit*, §14), and it is the oracle every cartridge with input takes (`CART.4`; §7.6). (*Version 4*, `ENGINE.18`: the sheet a person shows is such a row, `Input!B19`, so a game that reads it replays, §3.3.) (*Version 5*, `ENGINE.25`: and so is a command a person runs, `Input!B20`, §3.10.) (*Version 6*, `CART.12`: and an act's place and press at rate 0, §3.3; the release is the engine's, a function of the act.)
5. **Arithmetic is IEEE 754 doubles,** the language's `f64`, VBA's `Double` and Excel's own (*shelf*: `HORIZON.md` §12.2). WebAssembly's floating-point operations are deterministic except for the payload bits of a NaN (*exhibit*: the specification's nondeterminism note, §14), and a module with an empty import section computes every function inside itself, its transcendental functions included, so the same module gives the same bits on every browser; the native runner may differ from the module in the last bit of a transcendental function, since its library is the platform's, which is why a replay golden is held on the module and a floor is held on the runner (*recommendation*; `CART.1`, `CART.4`). (*Corrected 2026-10-09*, `CART.1`'s scoping, decision 4: a floor is held on the runner and on the module both, since one build of the language moved the native step by 55% and the module's by 35%, the two measured apart by a factor of 1.4 (*measurement*); `tools/check_frame_floors.ps1` holds four rows, native and wasm, Life's soup and the glider gun, and the runner's check mode holds a frame's allocations, the one number of the step that is the code's and not the machine's.)
6. **A budget never changes a value.** A step chunked by any budget computes the same frame as a step with none.
7. **Threads, SIMD and every accelerator are invisible.** An accelerator's frames equal the naive evaluation's frames, cell for cell, or it is not merged (`ENGINE.6`; `SD-18`'s shape); threads are a device after a measurement and change no rule above.
8. **The step computes values and never formulas.** A formula enters the grid by `load` or by a `write` made on a person's act, and the host's derived writes carry values alone; the formula cells after a step are the formula cells before it, cell for cell (`AD-7`, §9; decision 22).

What a replay cannot prove: the host's draw and sound, which are measured (frame times, floors) and never golden, by `AD-4`'s line.

## 7. The cartridge

### 7.1 One file

A cartridge is one text file, UTF-8, `.vla`, a form and then rows: the manifest form first, `(cartridge "<name>" ...)`, then the grid's rows, one a line, in the notation the treaty's oracles print (*shelf*: oracles 8 and 11). One file is what every console shares: a `.p8` is one text file with sections, a `.tic` one file of chunks, a uxn `.rom` one file (*exhibits*); one file is what a file input can pick and a person can share, diff and read. A folder of files, the manifest naming them by path as the distro manifest does (*shelf*: `core/src/distro.rs`), is the source layout a tool flattens into the one file, and is not what the engine loads; the tool is a later item's. (*Corrected 2026-10-10*, version 3: the tool is the pass of §7.8. A cartridge's source is the file a person writes, VLA with template macros, naming the other files it reads by path through `include`; the pass expands it into the one file, the artifact a person reads, saves and diffs; and the engine loads the one file alone.) The file carries its license as its first comment line, `; SPDX-License-Identifier: 0BSD` for a cartridge in this repository, the rule `REPO.2`'s license check holds over `cartridges/` (*shelf*: `REARVIEW.md`, `REPO.2`, decision 5), and a cartridge of one's own carries its author's.

### 7.2 The manifest

One `(cartridge "name" ...)` form, one directive a line, every directive given (nothing defaulted, so that the file says what it is; *recommendation*, the owner's rule against hidden defaults), read by the engine as the distro manifest is read and refused by name with what is wrong:

```text
; SPDX-License-Identifier: 0BSD
(cartridge "life"
  (spec 3)                     ; the version of this page the cartridge is written to; a (spec 1) or (spec 2) cartridge loads too
  (title "Life")               ; what the host shows
  (rate 30)                    ; frames per second, 0 to 120; 0 is a step on every edit (section 5)
  (screen plane 320 200)       ; plane|grid, width, height, within the limits of section 10
  (seed 1)                     ; a whole number, or host
  (author "Spreadsheet Company")   ; optional
  (license "0BSD")             ; optional, an SPDX identifier, the header's twin
  (notes "..."))               ; optional, a paragraph for the person who loads it
```

The name is lowercase letters, digits and hyphens, as a distro's is (*shelf*). `(seed host)` asks the host for a seed at load, the one place the wall clock may enter a cell, and the replay records what it chose. (*Corrected 2026-10-10*, `ENGINE.3`: no clock enters a cell; the host's seed is the browser's random number, §3.5, and a replay's header names it, §7.6.) A directive this version does not know is refused by name, so that a cartridge written to a later page fails loudly on an older engine, which is also what `(spec ...)` is for; every version 1 cartridge loads under version 2, and every version 1 and 2 cartridge under version 3, which adds no directive (§4.2); and every version 1 to 3 cartridge under version 4, which adds no directive either, its two rows a `(spec 4)` cartridge's alone (§4.2; `ENGINE.18`); and every version 1 to 4 cartridge under version 5, which adds none, its sheet and its row a `(spec 5)` cartridge's alone (§4.2; `ENGINE.25`). (*Corrected 2026-10-14*, at the owner's word that the page and the engine spell American English: the optional directive is `license`, in every version. Until that day it was spelled the British way, and a cartridge that still spells it so is refused as a directive this version does not know: respell the line or drop it, since it is optional. No release carried the earlier spelling.) A cartridge says the version of the rows it uses: the three in this repository say `(spec 2)`, written before version 3 and using nothing it adds, and their measured rows stand as they are (decision 32).

(*Version 6*, `CART.12`, decisions 57 and 66.) `(settle K)`, optional, a `(spec 6)` cartridge's alone and at `(rate 0)` alone: after an act the grid steps again while it moves, at most K steps an act, K a whole number from 1 to 65,536 (§5, §10). A cartridge without it steps once an act, as before. It is refused by name, `cart-manifest-invalid`, in a cartridge written to 1 to 5, whose page has no settle, with a rate above 0, where a tick steps the grid and no act settles, and out of its range.

It is refused by name, `cart-manifest-invalid`, in a cartridge written to 1 to 5, naming no sheet or a sheet twice, and, at the load, naming a sheet the cartridge does not hold.

(*Version 6*, `SPEC.5`, decisions 68 to 72.) ### 7.3 The rows

The rows are the relation rows `reflect` and `view` print, so that **what a door prints, the engine loads**: `load` is the inverse of `view`, and a sheet viewed whole and loaded again is the same sheet (*recommendation*; the oracle in §13). They are also what the pass writes (§7.8): a source's macros expand into nothing but these rows, and the load takes no other form, so that every convenience of authoring stays in the source, and a port of the engine implements none (decision 29). The kinds this version takes, in the printers' spelling (*shelf*: `core/src/reflect/print.rs`, oracle 11):

| row | meaning |
|---|---|
| `(sheet "<name>" visible\|hidden)` | a sheet, in tab order; optional, since a cell row makes its sheet |
| `(cell "<sheet>" "<addr>" <value>)` | a value: a number as written, a text in quotes, `true` or `false`, `(error "#NUM!")` |
| `(cell "<sheet>" "<range>" <value>)` | every cell of the range holds the value; the one addition to the printers' rows, so that a border is one row |
| `(formula "<sheet>" "<addr>" "=<text>")` | a formula, A1 references, the bar's spelling |
| `(formula "<sheet>" "<range>" "=<text>")` | the formula filled over the range, its relative references moved as Excel moves a filled formula, which is how a rule covers a Screen in one row and how `KERNEL.20` sees one shape |
| `(name "<name>" "<refers-to>")` | a defined name |
| `(column ...)`, `(format ...)`, `(style ...)`, `(gridlines ...)` | the looks, as the record prints them; grid mode draws them, plane mode keeps them |
| `(sentence "<sheet>" "<addr>" <row>)` | the program row that wrote the cell, kept for the sentence pane (`SD-35`), read by no rule |
| `(table ...)`, `(refers ...)` | carried as data in this version; a Table's lookups wait on `KERNEL.8` |
| `(look "<sheet>" <value> <index>)` | the look map: every cell of the sheet whose value is `<value>` draws with style `<index>` in place of its own, which is the Palette in the record's own terms; asked of oracle 11 after the `format` rows (decision 19) |
| `(row "<sheet>" <n> <height\|none> shown\|hidden)` | a row's height and visibility, the twin of the `column` row, asked of oracle 11; a viewport without it draws the default height |
| `(value "<sheet>" "<addr>" <value>)` after a `formula` row | the formula's last value, as a save prints it (§4.5, §7.5); taken as the cell's value until the first step, never a second write of the cell |

R1C1 is not an input notation in this version: a filled formula gives the same one shape, and the view record prints A1 (§12).

(*Corrected 2026-10-12*, `ENGINE.8`, as the viewport reads the two rows decision 19 added.) A `look` row's value matches a cell's as §3.1 says: a number by its value, a text by its characters, a truth value, an error by its name, the first look the record holds for a value winning, and an empty cell or a formula with no value matched by none. A `row` row's height is in points, as Excel's is, and a viewport draws it at 96 dots an inch.

**One write per cell.** A cell the rows write twice, by two rows or by a range and a row over one of its cells, is refused at load by name with both lines (§4.2; decision 23), so that the file says one thing about each cell and a collision is loud rather than last-wins. That is the prelude's own doctrine for a template macro's bindings, two uses of a name colliding loudly at VBA's compile step rather than hidden by a hygiene mechanism (*shelf*: `scripts/prelude.vla`), carried into cells, where nothing but the loader can be loud (`docs/ALGEBRA.md` §2.4).

### 7.4 Frazaro is the compiler

A game written in English is translated by Frazaro at build time and ships as VLA (`CHARTER.md` §4, rule 1): `frazaro build` builds the program into the sheet model and `frazaro view` prints any sheet of it as rows (*shelf*), so a cartridge compiled from English is the manifest followed by the view of each sheet, the `Frazaro` sheet with the sentences included, and the `(sentence ...)` rows link every cell to the sentence that wrote it. The same road takes any workbook: `frazaro reflect book.xlsx` prints its sheets as rows, and a manifest in front of them is a cartridge, which is the thesis as a command line, a spreadsheet being a game whose frame rate is one. The engine reads no English and no `.xlsx`; the rows are the whole interface between Frazaro's module and this one, two modules on one page, one text between them, and `alonzo` never depends on `frazaro-core` (`AD-1`). A cartridge written in VLA takes the other road, through no door of Frazaro's: its macros are the language's, expanded by the pass (§7.8) with the language's own expander, so that a game's build needs the language and never the core (`CHARTER.md` §4, rule 1; decision 26).

### 7.5 A save is a cartridge

On a `save` edge (§3.7) the host asks `view` for every sheet that is not a twin, whole, and writes the manifest it loaded followed by those rows, with the Clock's frame as it stands, under the name `<name>-<frame>.vla`; `load` of that file resumes the game at that frame with the same seed, since the state is the cells and nothing else. The Input sheet's rows are saved too, as values, which is harmless and honest. The twins are not saved, being derivable: a loaded save's twins are filled with its values, so the first step after a load reads a previous frame equal to this one, which a rising edge sees as no edge, the right answer.

### 7.6 The replay

A replay is the log of writes between steps, with the cartridge and the seed named, so that playing it back is issuing the same writes before the same steps:

```text
(replay "life" (spec 2) (cartridge "<sha-256 of the cartridge file, upper-case hex>") (seed 12345))
(frame 1)
(cell "Input" "B5" 1)
(frame 2)
(cell "Input" "B5" 0)
(frame 3)
...
```

`(frame n)` heads the rows written before the `n`th step; a frame with no row is a frame with no change, and a host may log only the cells that changed, since a write of the value a cell already holds changes nothing. The host's derived writes (§3.9) are not logged, being a function of the frame: a replay re-derives them, and the one way they could differ is a changed cartridge, which the digest refuses. The golden of a replay is a sheet at its end, as `view` prints it, compared whole: `CART.4`'s Board, `CART.1`'s Screen at generation `n` against Golly's (*shelf*: `ROADMAP.md`). (*Corrected 2026-10-09*, `CART.1`'s scoping, decision 2: Life's Screen is held at every frame to a Life written by hand, by the native runner and by the page's instrument, the plane compared whole; and the glider gun to its published facts, period 30, 36 cells and 5 more a period, through generation 720, before its first glider meets the dead border at 740, where the cartridge's bounded plane and Golly's unbounded one stop agreeing (*measurement*, the runner's Life). A cartridge with no input has an empty replay, so its golden is the reference's frame.) A replay names the spec version and the cartridge's digest, since a replay against another cartridge or another page is nonsense, which is Doom's caveat too (*exhibit*). (*Noted 2026-10-10*, version 3: the digest is the cartridge's, the pass's output, and never its source's, so that the file a replay names is the file the engine loaded. The pass carries no comment and its banner no digest, so a cartridge's bytes move only with its rows, and a source's comments never orphan a replay.)

(*Corrected 2026-10-10*, at the owner's word after `ENGINE.3` closed: a frame is one form holding its rows, `(frame 1 (cell "Input" "B5" 1))`, where the example above writes a `(frame n)` head and the rows after it. ### 7.8 The source and the pass

*Version 3's, 2026-10-10 (`SPEC.3`, decisions 25 to 35).* A person writes a cartridge as a source, VLA with template macros, and the pass expands it into the rows of §7.3, the one file the engine loads. The pass is how the house's macros do the rote work of writing rows, and it is written for the owner's principle, given at the approval: "hand-typing boilerplate is not conducive to rapid iteration, and rapid iteration is the psychological barrier between creative flow and task abandonment". So the pass knows no macro by name. Every macro is an author's, in the source or in a library the source includes, and the repository's library, `cartridges/common.vla`, is a file like any other, written to be read, copied, changed and outgrown. A palette is one call there, a pattern one call a row of it, a run of rows on one sheet one call that names the sheet once, and a patch one call a module (Appendix C).

**The act** (*recommendation*; decision 25, the owner's refinement of 2026-10-10). The pass is an act of its own between the source and the load. The load takes rows and never expands; the pass takes a source and the texts it includes, writes rows, and never loads; a door may run the load after the pass, as an act of its own, to say whether the cartridge loads. The pass's output, the cartridge, is the artifact a person reads, saves and diffs, and where the pass runs is not what it is. It is one pure function of its texts in the engine's crate (`engine/src/pass.rs`), over the language's own expander, with two doors, the command line (`cargo run --release --example expand`, which writes each cartridge beside its source and then loads it) and the page (`alonzo_expand`, §4.6, the engine panel's Build, a press of its own before Load, which puts the cartridge where it is read before anything loads it), giving the same bytes (decision 26).

**The source**, in this order:
- its license, the first line (§7.1), which the cartridge carries as its own first line;
- any `(include "path")` line;
- template macros, `(defmacro ...)`, anywhere, each defined before any form expands, as the language's first pass defines them;
- the manifest, the first form that is no macro, copied as written and never expanded, so that the source states what the cartridge is;
- then the rows of §7.3 and calls of macros, in any mix.

A source is named `<name>.source.vla` and stands beside the cartridge it writes, `<name>.vla`, in the cartridge's folder (decision 28).

**The include** (decision 27). It is the reference's, `VLA.bas`'s P.L7:
- a line holding the form alone, spliced where it stands;
- its path resolved against the source's own folder, as the reference resolves against the workbook's, the includes of an included text too;
- nested at most 16 deep;
- refused with the language's own ids: `vla-include-cannot-read`, `vla-include-too-deep`, and `vla-include-must-stand-alone` for an include inside a form or beside one.

The pass reads no file. Each door hands it the texts the source may include, under the paths they resolve to: the command line reads them from disk, and the page passes the ones it embeds.

**The pass, in order:**
1. the includes spliced, each included form standing on its include's line for a refusal;
2. every `defmacro` defined by the language's expander;
3. the manifest found, the first other form, and copied;
4. every form after it expanded to its fixpoint by the language's expander: template substitution, the rest parameter, the quasiquote bundle and the seventeen expand-time primitives (twenty-seven since `vla-lang` 0.9.0, *corrected 2026-10-11* below, and `formula-expand` since 0.10.0, *corrected 2026-10-22* below), with no gensym and no eval;
5. each `begin` flattened, a `begin` being no row;
6. the cartridge written: the source's license line; a banner, `; Expanded by the pass from <name>.source.vla: edit that file, then expand it again.`; the manifest one directive a line; and the rows one a line; CRLF, as every `.vla` stands in the working tree.

The pass judges no row. A form the load would refuse is written, and the load refuses it at its line in the cartridge, one form a line. A refusal of the pass itself stands on the source line of the form that raised it. The banner holds no digest, so a comment edited in a source never moves its cartridge's bytes.

**The golden.** Every cartridge with a source is the pass's expansion of it, byte for byte over LF.
- `cargo test` holds it, reading the folder, so that a cartridge added with its source is held without a line of code.
- `tools/check_cartridge.ps1` holds, statically, the folder rule, each source beside its cartridge and each banner naming its source.
- The loop oracle holds the page's pass to the command line's bytes: its eleventh case, `pass`, expands every source the page holds over the module and compares each with its cartridge as the command line wrote it, CRLF; a build over the double is declined in words.

A cartridge with no source is written by hand and stays a cartridge, as every version 2 cartridge was.

**What a template macro reaches today** (*measurement*, 2026-10-10, `vla-lang` 0.8.1; `REARVIEW.md`, `SPEC.3`):
- *A row, by arithmetic.* `(+expand row 1)`, and an address fused from it: `(symbol "\"A" (+expand row 1))` is the text `"A1"`, since `symbol` makes a string of a fused text that opens on a quote mark.
- *A column and a sheet, only by the names its caller writes.* No primitive turns a column's number into its letters.
- *A formula's text, fused from atoms.* `(symbol "\"=IF(MOD(Clock!B1,C" row ")=0,1,0)")` is a formula a module writes. A flat expression becomes a formula too, but not a nested one, since a macro cannot call itself inside `symbol` (`vla-symbol-arg-is-list`).
- *A list, by recursion in tail position.* The trampoline keeps the rows flat: the three cartridges' expansions nest 3 deep. A chain stops at 5,000 applications, and each step copies the rest of the list, so a walk over dozens of items costs nothing and one over a Screen's 64,000 about four seconds.
- *Never a text split into its characters.* A picture written as a string is no macro's (§12).
- *The template doctrine's one trap.* A parameter replaces its name everywhere in the template, a row's head included, so a parameter is never named like a row it writes: a parameter `name` turns `(name name ...)` into a row the load refuses.

The generality the owner's principle asks for, at the row, the column and the sheet, is the language's to give, and §12 names it as the pass's next step.

(*Corrected 2026-10-11*, the pin at `vla-lang` 0.9.0, Frazaro's `VLA.3`: that step is given.)
- Ten primitives join the seventeen, twenty-seven in all, each refusing by name what it cannot compute: a fraction to divide, a zero divisor, a row or a column past Excel's limits, a text that is no address. The ten:
  - `-expand` and `*expand`;
  - `quotient-expand` and `mod-expand`, Excel's `QUOTIENT` and `MOD` over whole numbers;
  - `&expand`, its atoms joined into one text, so that an address or a formula's text needs no leading quote mark: `(&expand "A" (+expand row 1))` is the text `"A1"`;
  - `characters-expand`, a text split into its characters, so that a picture written as a string can become cells;
  - `address-expand`, `"B3"` for row 3 and column 2;
  - `row-expand`, `column-expand` and `column-letters-expand`, an address or a column read back.
- So a template macro reaches a column by arithmetic as it reaches a row, and the list above, measured at 0.8.1, stands corrected in its second, third and fifth points.
- The library's `keys-from` joins its addresses by `&expand` since the same day, every cartridge expanding to the same bytes. Appendix C's patch, written before, fuses its addresses by `symbol` still, which still works.

(*Noted 2026-10-12*, `KIT.1`, the kit's first verbs; *measurement* over `vla-lang` 0.9.2. `REARVIEW.md` holds the scoping, its eleven decisions and the build.)
- The library holds the patterns two cartridges wrote alike by hand, or one wrote as this page spells it. `sheets`, `labels` and `headers` write a cartridge's sheets and their words; `default-keys` writes §3.4's table; and the verbs `first-frame`, `pressed`, `count`, `hold` and `dice` write §3.3's rising edge, §3.5's dice, §3.9's keep-last and the first frame's test. - A verb writes one formula row: the sheet first, so that `on` names it once; then the range it fills; then pieces of a formula without the `=`, each a string or an `&expand` of strings, written as the range's first cell reads it. `(count "Tally" "B16" "Input!B16")` writes `=Tally.last!B16+Input!B16`.
- A macro's call is no argument of `&expand`, since the expand-time primitives take their arguments as data, and the language refuses one, `vla-expand-arg-is-list`, at the caller's line. So verbs compose by reference, one writing a cell that another reads. A macro that finds a text, a range's first cell or a reference's twin, hands it on to the macro named after it: `(first-cell range then args...)` becomes `(then first args...)`, a walk of an application a character.
- A verb builds its row inside a quasiquote, its pieces spliced in by `unquote`, so an `&expand` piece is joined when the row is expanded. Named inside the verb's own `&expand`, a parameter bound to an `&expand` form would be handed over as the list it is, and refused.
- The pass over a source costs a few tenths of a millisecond more, the library's longer text read and its macros defined before any form expands.

(*Corrected 2026-10-22*, `KIT.5`, the kit and every cartridge over the formula syntax; the pin at `vla-lang` 0.10.1. `REARVIEW.md` holds the scoping, its eight decisions and the build.)
- A twenty-eighth operation joined the twenty-seven with `vla-lang` 0.10.0, Frazaro's `VLA.4`: `formula-expand`, which writes a VLA expression as a formula's text in Excel's own spelling, a reference bare, `Input!B5` or `Screen.last!A1:C3`, a test `(= State!B1 4)`, a sum `(+ a b c)`, and expands its expression first, so that a macro's call stands inside it and an expand-time primitive computes there, `(ref "Probe" (&expand "$D" row))` for `Probe!$D1`. So the third point of the list measured at 0.8.1 stands corrected too: a nested expression becomes a formula, by the syntax and not by fusion.
- A verb's pieces are expressions, and the row it writes is a `formula-expand`: `(count "Tally" "B16" Input!B16)` writes `=Tally.last!B16+Input!B16`, and `(hold "B3" (or (= State!B11 1) (= State!B14 1)) (if (= State!B11 1) 1 (+ State.last!B3 1)))` its keep-last. `rule` and `rules` are the plain formula row and `formulas` over expressions; `formula` and `formulas` keep a text, for a formula the syntax cannot write back byte for byte, one with redundant parentheses, which Naught's verdicts hold.
- A predicate two verbs share is an expression macro and stands in either: `edge`, the rising edge as a test, and `twin-of`, a reference's twin as a bare reference, whose walk ends in `symbol` in its base case, since a macro's call is no argument of `symbol` either. A verb inside a verb's piece is refused by name, `vla-formula-expand-nested`, at the caller's line, each verb's row being a `formula-expand` of its own.
- Every cartridge of this repository is written over the syntax, each naming its repeated tests once as expression macros of its own, and every one expands to the bytes it had, `expand --check` eleven `same`.

(*Noted 2026-10-12*, `KIT.2`, the picture; *measurement* over `vla-lang` 0.9.2. `REARVIEW.md` holds the scoping, its twelve decisions and the build.)
- §12's picture is taken by the route it recommends, a macro over the object model: `(picture sheet top-left legend row ...)`, each string one row of cells down from the top-left, each character one cell, its value the legend's. A pattern, which this section's opening writes as one call a row of it, is now one call, its picture: the glider gun's Seed is one, and expands to the rows the nine calls of `live` wrote, which leaves the library.
- The legend is `hex`, PICO-8's sixteen digits, `0` to `9` and `a` to `f` the Palette's indices 0 to 15, as a PICO-8 cartridge keeps its sprites; or a list of entries, each a character and its value, a number, a text or a truth value: `(("O" 1))` writes a Life pattern's live cells. A dot writes no cell, in every legend, which the plane reads as 0 (§3.1) and the composite, when it comes, as transparent (§12).
- A character the legend does not hold writes a row the load refuses, `(not-in-the-legend sheet cell character)`, where its cell would be. The pass judges no row, so the load refuses it at its line of the cartridge, and that line names the sheet, the cell and the character.
- What a picture costs, the pass natively and in the page: a sprite a millisecond or two, PICO-8's 128 by 128 sheet about a tenth of a second, and the Screen whole, 320 by 200, about half a second, its 64,000 cells loading in a tenth more. A chain counts its links, each application and each `begin` a macro made, and the other forms of such a `begin` are chains of their own, so a picture stops at 2,499 rows, or at a row of 2,499 cells.
- The four seconds measured at 0.8.1 for a walk over the Screen's 64,000, in the list above, are 0.14 s at 0.9.2, where a walk that hands its list on whole costs its length (Frazaro's `VLA.2`); one that splices its rest still copies it at every step.

(*Noted 2026-10-14*, `ENGINE.9`, the size ladder; *measurement* over `vla-lang` 0.9.2. `REARVIEW.md` holds the scoping, its eleven decisions and the build.)
- A source states a parameter as a macro with its value, and a door builds the source at another value. The pass gains one function, `expand_with(source, path, files, definitions)`, whose definitions, VLA text, stand after the source's last line. Every `defmacro` is defined before any form expands, and the language's expander keeps a name's last definition, so a macro the definitions define overwrites the source's of the same name wherever the source calls it.
- The pass still knows no macro by name. The page does the same act by appending the same text to the source before `alonzo_expand`, whose arguments are unchanged; the empty text is the pass itself; and a refusal of a definition's form stands on its line, counted past the source's last.
- A parameter that an expand-time primitive needs is handed on, as the kit's walks hand on what they find, since a macro's call is no argument of a primitive: `life.source.vla` and `gun.source.vla` state their board as `(board-size then args...)`, which becomes `(then 320 200 args...)`, and write their rule over the kit's `interior`, which computes the interior's address from the size. Both expand to their bytes.
- The size ladder builds both at 640 by 400 and at 1280 by 800 by a later `board-size` that writes a still Camera at the board's top-left before handing the size on, the window staying the manifest's (§10). This is the size knob `CART.9`, `CART.11` and `CART.12` name.

(*Noted 2026-10-16*, `ENGINE.7`, edit and continue; *measurement* over `vla-lang` 0.9.4. `REARVIEW.md` holds the scoping, its fifteen decisions and the build.)
- A rebuilt source is applied to the running game, its state kept, by an act of its own beside Build and Load: the page's Apply the source builds the source as Build does and applies the cartridge it writes, the host's `apply`. The load begins a game at frame 0; a continue keeps the frame number and every cell the rebuilt cartridge does not change, and the rules change from the frame its rows land in.
- The rebuilt cartridge is compared with the one the grid was last given, the one loaded or the one last applied, row by row. A `cell` or `formula` row is keyed by its sheet without case and its address or range, and compared as the reader spells it back, so spacing is never a change. Every row the source changed or added is written, a formula's and a value's alike; a row it left alone is never written, so a cell the run moved keeps what the run gave it; and a `value` row, a formula's value before its first step, is neither written nor compared.
- What a write cannot carry is named in words, Load offered, and nothing is written: a directive of the manifest; a sheet added or removed, or a `sheet` row's order or visibility; any row that is not a cell or formula row, since a write takes `cell`, `formula` and `derived` rows alone; and a cell a removed row wrote that no row of the rebuilt cartridge writes, since no write empties a cell. A device's layout follows the manifest and the sheets.
- The rebuilt cartridge is first loaded in a second handle of the module and given back at once, so a continue applies nothing a load would refuse, a cell written twice among it. Then its rows are one write, all or none, in the place of a person's edits at the next frame's start (§5, step 3): a refused write changes nothing, and the game runs on under the rules it had. The frame after a formula row is computed whole, as a formula's write makes it, and its window's changes are whole (§4.5).
- A continue needs no twin at the command line: its replay is the twin, played by the engine's own player as every committed replay is.
- What it costs, the scoping's probe in Chrome 155: Buffet's rule applied at frame 1,806 in 9 ms, where Build, Load and a replay back to the frame took a minute at its rate; Sand's Stay rule, 62,568 cells, in 0.31 s, 0.16 of it the second load and 0.12 the write, where the route took 35 s.

## 8. The host

### 8.1 The exports

The twelve names of §4.6, eleven functions and the memory, and nothing else (*noted 2026-10-10*, version 3: the twelfth, `alonzo_expand`, the pass, which a host asks for when a person builds and not when it attaches the module, since the page's double holds no pass). A page instantiates the module with an empty import object, reads `alonzo_abi_version` and refuses a number other than this page's, as the Frazaro page does with the core (*shelf*: `web/index.template.html`).

### 8.2 The imports: none

**The engine's import section is empty in this version** (*recommendation*; decision 1, the one this page most wants the owner to read). Every device above is a sheet the host writes before a step or reads after one, through the exports: the Screen and the Audio are read, the Input is written, the Clock is the engine's own, the File is a picker whose bytes come in through `load` and a download whose bytes go out through `view`. Nothing in the frame needs the module to call the host, because the loop lives in the host, and the one thing an import buys, a call out of the module in the middle of a step, nothing here wants. So the allowlist `REPO.2` holds stays at its count of zero, which is the same fact `frazaro-core` proves on its artifact, and it means more here: a module with no imports is a pure function of its inputs, bit for bit, which is what makes rule 5 of §6 true across browsers and makes `SD-13` a property of the file rather than of the shim. The charter's §2 expected imports, "because a game must draw, sound and listen, and every one of those is the host's function"; the sentence is true of the host and this page keeps it there. Both were amended on 2026-10-08 at the owner's approval: §2's "will have imports" reads "may have", and `AD-5`'s second sentence begins "Each import, when one is needed,", the rest unchanged, since the rule's substance, no generated glue and no second dependency, holds exactly as adopted. The alternative, declined: `alonzo.blit` and `alonzo.note` as imports the engine calls, which would put the draw inside the step, cost native tests a stub for every import, and buy no frame this version can draw sooner. The day a device needs an import, threads being the one candidate this page can name, it is declared under the one module name `REPO.2` chose, `alonzo`, listed in §3.11 and in the allowlist with the count beside it, and read in review.

### 8.3 The shim's duties

blits the plane through the Palette, crisp (`ENGINE.2`), or draws the record through the viewport (`KERNEL.5`; *noted 2026-10-12*, `ENGINE.8`: its own viewport, over an element the page hands it, the Input device over the viewport's cells; ### 8.4 Adding a device, or an optimization

A contributor adds a device by writing its sheet into §3, its direction, and its row in §8.3; then its code in the shim and, where the engine checks a layout, in the engine; then a cartridge that uses it under `cartridges/` with a replay golden. ## 9. Reflection, sanctified

The owner's rule of 2026-10-08, adopted the same day as the charter's sixth rule (`CHARTER.md` §4) and the register's `AD-6` (`ROADMAP.md`): **`AD-6`. Everything the engine holds is a cell of a named sheet, viewable through the one view call and, except the twins and the plane, writable through the one write call; a device is a sheet's layout on this page, and no device holds state that is not a cell.** What it buys: a player opens the Keys sheet and rebinds a button; a modder opens the Palette and recolors a game; an auditor opens `Screen.last` and sees the previous frame; a teacher opens the Clock and slows the rate to one frame a second to watch a rule think; a tester opens the Input sheet and writes a press by hand; a game's difficulty is a cell anyone can read, which is `CART.4`'s claim against the cabinet; and every one of those acts is a row in the one notation, logged by the replay, printed by the door. The engine keeps nothing a program cannot see except the progress of a yielded step, which it reports, and the host keeps nothing but `SD-23`'s interface state. This is the Lisp machine's property kept where it was cheap, in the data, and Emacs's property that the running system is inspectable and changeable from inside, in its own language (`CHARTER.md` §5): the owner's phrase for the target, 2026-10-08, is Emacs and Excel at once, and the table reads it literally (*recommendation*):

(*Noted 2026-10-12*, `CART.4`, Kairos.) The claim against the cabinet is a sheet: the Levels sheet holds each level's period, the frames the row holds a place, its width, and its window, the frames of a place in which a press stops the row where it stands, a later press stopping it a column on. The window is the cabinet's rigging made a cell, its operator's setting by the encyclopedia's account (§14). Every window equals its period, so the game is honest, and an edit such as `(cell "Levels" "D3" 1)` rigs a copy in the open, the replay logging it.

**`AD-7`**, proposed by version 2 (decision 22) and adopted by the owner 2026-10-08 at its approval, the charter amended first as `ROADMAP.md`'s register requires (`CHARTER.md` §4, rule 7): **the step computes values and never formulas; a formula enters the grid by `load` or by a `write` made on a person's act, and the engine's own effects write values.** What it keeps is eval by a person, the REPL, which the table's `M-:` row celebrates; what it refuses is eval by the program, a formula computed at run time and installed, which the owner's veto of `GENSYM` already carries by its own words (§3.9) and which would make every static property of this page, the cycle check at load, the vectorized shape, the clock calculus and the linear-region pass of `docs/ALGEBRA.md` §6, a per-frame property. Held by a test and not a sentence: the formula cells before and after a step are equal (§13). The sacrifice is smaller than it looks: what the Lisp machine had was a REPL, macros and `eval` from running code; the first two stay, at the viewport and at build time, and the third goes, the one least used even there (`docs/ALGEBRA.md`, the sitting of the veto's reach in `REARVIEW.md`).

What reflection does not reach, by name: the host's own state (§8.3) and the module's heap, which are not cells and are not meant to be.

## 11. The decisions, the owner's

Each with the draft's recommendation, which the sections above assume, and the alternative it declined. The first five are the roadmap's; the rest the drafting found. *All seventeen approved by the owner on 2026-10-08, and `AD-6` adopted; the alternatives stay recorded so that a later reader knows what was weighed.*

1. **Zero imports; the host pulls.** The engine exports and never imports; every device is a read or a write through the exports; the allowlist's count stays zero; the charter's §2 and `AD-5` get the two amendments §8.2 words. *Alternative:* `alonzo.blit` and `alonzo.note` as imports, the charter's first picture. Recommended: zero imports.
2. **The previous frame is a sheet, `X.last`.** Read-only, filled at the end of every step, listed hidden, viewable. *Alternative:* a function, `LAST(ref)`, in the evaluator. Recommended: the sheet, for the reasons of §2.
3. **An explicit handle.** From `load`, taken by every call, never reused. *Alternative:* one implicit grid per module instance, a second cartridge needing a second instance. Recommended: the handle.
4. **The palette: sixteen entries in a Palette sheet.** The index a byte, so the count can grow by a version of this page. *Alternative:* a free RGB value per Screen cell, three bytes a cell, no palette, arithmetic on colors awkward and the record noisy. Recommended: the Palette sheet.
5. **The Input sheet's cells:** ten buttons for four players, the pointer in Screen cells with three buttons and the wheel, the last key as `key` and `code`. *Alternative:* PICO-8's six buttons, or a full key matrix now. Recommended: the eighteen rows of §3.3.
6. **The Clock holds three cells,** frame, rate and seed, and nothing from the wall clock. *Alternative:* the frame number alone, the seed elsewhere; or an elapsed-seconds cell the engine computes. Recommended: the three.
7. **Volatile functions are refused at load,** `NOW`, `TODAY`, `RAND`, `RANDBETWEEN`, naming the Clock. *Alternative:* `RAND` served from the seed by the engine, which hides the dice. Recommended: refuse.
8. **The resolution: at most 320 by 200,** any smaller size declared by the manifest. *Alternative:* exactly 320 by 200. Recommended: the maximum, so a 128 by 128 cartridge is honest about its size.
9. **The Keys sheet,** the key map as data the host reads. *Alternative:* the map in the shim, fixed. Recommended: the sheet, for §9's reasons.
10. **Grid mode is a cartridge mode,** `(screen grid w h)`, drawn by the viewport. *Alternative:* plane only, text games deferred. Recommended: both modes, since the viewport exists for the first game anyway and the cell is the unit in both.
11. **One file, manifest then rows, with `(cell|formula "<sheet>" "<range>" ...)` fills.** *Alternative:* a folder with a manifest naming files, as a distro is. Recommended: one file for the engine, the folder as a source layout a later tool flattens.
12. **Every manifest directive required,** no defaults. *Alternative:* `rate` 30 and `seed` 1 when absent. Recommended: required.
13. **The error color is magenta and fixed,** byte 255 and any byte past the palette. *Alternative:* draw them as color 0. Recommended: magenta, so an error is seen.
14. **A `value` row joins the view record** after each formula row once values exist, `KERNEL.7`'s amendment to oracle 11, named here. *Alternative:* the record shows formulas as text only and values are read through the plane alone. Recommended: the row, so the record remains the oracle of the plane.
15. **`AD-6`, reflection,** as §9 words it. *Alternative:* leave it as a habit. Recommended: bless it, since every later device will be designed against it.
16. **The audio voice is wave, note and volume,** the graph's own words and a MIDI number. *Alternative:* frequency in hertz. Recommended: the note.
17. **The page's license stays CC-BY-4.0** under the map's `*.md` rule, so a port may quote it with attribution. *Alternative:* a code license for the specification. Recommended: as the map has it.

*Version 2's decisions, 2026-10-08 (`SPEC.2`), argued in `docs/ALGEBRA.md` §2 and §3; all seven approved by the owner the same evening, and `AD-7` adopted, which amended the charter the same hour; the sections assume them, and the alternatives stay recorded.*

18. **The grid writes the grid, in values: the Write sheet** (§3.9). A table of `sheet`, `address` and `value` the host carries into the next frame as `cell` writes, refused by name into a formula cell, a twin or a host-written cell, applied before the frame's own writes, never logged by the replay. *Alternatives:* keep-last formulas alone, version 1's only state, a frame axiom per cell re-evaluated every frame; or formula rows beside the value rows, the program writing code, declined under the `GENSYM` veto's `eval` clause the same hour it was drafted. Recommended: values only.
19. **One model, two renderers** (§1, §3.1, §7.3). A sheet holds values; its look is a declared map from a value to a style, the Palette for the plane and a `look` row for the grid, with a `row` row as the `column` row's twin, both asked of oracle 11; version 1's "fills that change per frame" is withdrawn from §12, `SD-32` kept whole since the map is declared and only the value changes. *Alternative:* two modes, the fills of grid mode fixed, and a stacking game's score unable to share a sheet with its blocks. Recommended: one model.
20. **Rate zero** (§5, §3.5, §3.3). `(rate 0)` steps on every edit, the frame number counts edits, the Input sheet is not written, derived writes trigger no step. *Alternative:* the spreadsheet as a special case the host handles outside the manifest, which would make the first game the one cartridge the loop does not describe. Recommended: rate zero.
21. **The Camera sheet** (§3.8). Two cells the host reads after a step and passes as the view call's window; the Screen's declared size becomes the window's, the sheet any extent. *Alternative:* an offset every Screen formula reads through `INDEX`, the window's every cell a lookup a frame, the whole budget on scrolling (*derived*, `docs/ALGEBRA.md` §3). Recommended: the sheet.
22. **`AD-7`, held by a test** (§2, §6 rule 8, §9). The step computes values and never formulas; the formula cells before and after a step are equal, a `vla-lang` test on every fixture. *Alternative:* the veto cited in prose, with nothing on the artifact to hold it. Recommended: the test, and the owner's amendment of the charter first.
23. **One write per cell** (§7.3, §4.2). A cell the cartridge's rows write twice is refused at load with both lines named. *Alternative:* last wins, silently, as a sheet would otherwise do, and the prelude's loud-collision doctrine silent in cells. Recommended: refuse.
24. **The limits restated** (§10, §4.6). ## Appendix B. Four formulas a cartridge writes

- **A button's rising edge** (`CART.4`): `=AND(Input!B5=1, Input.last!B5=0)`.
- **A counter that wraps with the clock**: `=MOD(Clock!B1, 8)`, the phase of an eight-frame cycle.
- **A position under velocity** (the falling-block game, the sand): `=State.last!B2 + State.last!B3 / Clock!B2`, the last frame's position plus the last frame's velocity over the rate, with the collision as the comparison that clamps it.
- **A tower cell frozen by a write** (the stacking game; `docs/ALGEBRA.md` §4): `Write!A2` holds `Tower`, `Write!C2` holds `1`, and `Write!B2` holds `=IF(AND(freeze, lit1), "A" & State!B2, "")`, one such row a column of the slider, so that on the frame the button freezes a lit block the host writes a 1 into the Tower as a value, and the Tower holds no formula however tall (§3.9); the Camera's row cell, `=MAX(1, State!B2 - 12)`, keeps the window on the top of it (§3.8).

**C.2 What it expands to.** The pass expands the macros into rows (§7.8; *corrected 2026-10-10*, version 3, where version 1 had Frazaro expand them and print the sheets), and the rows are the second file, the cartridge the engine loads. Three modules, one voice and the roll, so that the shape is visible; the rest follows the same pattern:


Every row above is a formula of this frame's cells and the twin, so the whole patch is one dependency graph with no cycle: `held` reads `bar` and `dice` this frame and its own last value; `env` reads `age` this frame; the roll's cells each keep their own last value except the one column under the playhead, which is how a trail is drawn with no state but cells. The dice is exact in doubles, since the seed and every later value are below 2^31 and 16807 times 2^31 is below 2^53 (*derived*; §3.5).

**C.3 The module library, `modular.vla`.** Template macros in the prelude's style, each writing its rows itself: a value into a cell, a formula's text fused from atoms by `symbol`, and the cable as a `(name ...)` row (*corrected 2026-10-10*, version 3; version 1's macros wrote the build walker's forms, `set!` and `set-formula` of a `cells` reference, for Frazaro to fold). Measured the same day, `SPEC.3`'s scoping: over the language's expander as published, these three write C.2's rows exactly, and a template macro loops by recursing over a list in tail position, so a scale takes as many notes as its caller gives. A parameter is called `label` and never `name`, since a parameter replaces its name in the `(name ...)` row's head too (§7.8):

```text
(defmacro (divide row label n)
  "a pulse: 1 on the frame a cycle of n frames begins, else 0"
  (cell "Patch" (symbol "\"A" row) label)
  (cell "Patch" (symbol "\"C" row) n)
  (formula "Patch" (symbol "\"B" row) (symbol "\"=IF(MOD(Clock!B1,C" row ")=0,1,0)"))
  (name label (symbol "\"Patch!$B$" row)))

(defmacro (hold row label source when)
  "sample and hold: take the source when the trigger is 1, else keep the last frame's value"
  (cell "Patch" (symbol "\"A" row) label)
  (formula "Patch" (symbol "\"B" row) (symbol "\"=IF(" when "=1," source ",Patch.last!B" row ")"))
  (name label (symbol "\"Patch!$B$" row)))

(defmacro (scale col & notes)
  "notes down a column, MIDI numbers, lowest first, as many as the caller gives"
  (quasiquote (scale-from (unquote col) 1 (unquote notes))))

(defmacro (scale-from col row notes)
  "the notes from a row on, a note at a time, in tail position"
  (quote-if (null? notes)
    (begin)
    (begin
      (cell "Scale" (symbol "\"" col row) (car notes))
      (scale-from col (+expand row 1) (cdr notes)))))
```

**C.4 What exists, and what waits.** The macros above expand under the language's expander as published, and the pass writes their rows (§7.8): the modules, the scale and the cables exist today (*measurement*, 2026-10-10). A `voice` form's expression arguments want the formula dialect, `(- note 12)` becoming `=note-12`. A template macro writes a flat expression so (`(symbol "\"=" (car (cdr e)) (car e) (car (cdr (cdr e))))`), and not a nested one such as `(* 0.2 env (- 1 drift))`, since a macro cannot call itself inside `symbol` (measured: `vla-symbol-arg-is-list`). The dialect is `frazaro-core`'s emitter today and the language's in time (§12), and until it is the language's an argument is the formula's own text, `"=note-12"`. The `(name ...)` row is in the cartridge format (§7.3), and a module writes its own cable. `Patch.last` and `Screen.last` are the language's (§2). `SIN` for the oscillator is `KERNEL.7`'s registry; `INDEX` and `MATCH` for the quantizer and the roll are `KERNEL.8`'s, with `CHOOSE` as the stand-in (§13). The `age` and `env` rows show why the caller names every cell: an envelope is two cells, and a macro that invented a hidden one would break the rule the whole language keeps. What a modder shares is either file: the patch as written, which the pass expands, or the saved cartridge with the knobs as turned, which loads; both are text in the one notation, so they diff in git, and the cartridge loads, views and reflects.

**C.5 Fragments in Fragments.** *Added 2026-10-08 at the owner's word, from the sitting's answer to two questions: how `fragments.vla` and `modular.vla` map onto a modular synthesizer, since the example seems to add no sine wave and no effect; and whether the artist's patch notes for the track, which the owner read as "an unstructured version of what I hope VLA could codify so that modular synth artists can pass around VLA patch files in the same way pianists pass around sheet music", can be so codified. The notes are quoted as the owner pasted them (§14).*

*Where the sine waves are, and why there is no effect.* A rack carries two kinds of signal. Control voltages move at the speed of a hand or a cloud: clocks, random voltages, envelopes, slow oscillators, probability. Audio moves at the speed of a string. This page puts the first kind in cells and rents the second from the Web Audio graph (§12). So `(lfo 4 "drift" sine 1800)` is a sine computed by a formula, one value a frame, a minute a cycle, a control signal; and `(voice 2 sine ...)` is a sine at audio rate, the host's oscillator, named by a word in the `wave` cell rather than computed. There is no effect because version 1's Audio sheet is a chip-tune voice, one oscillator and one gain per voice, the scope `ENGINE.4` was given; a filter, a delay, a reverb and a crossfader are rows of the patch sheet §12 names, the later version in which the graph itself becomes data. What the example shows in full is the control side of a modular system, which is where the artist says the week went: "most of that to fine tune many aspects, especially probability and setting attenuation and offsets to get just the right range of CV".

*On sheet music.* The analogy holds exactly, and it says where the line is. A score fixes pitches, durations and dynamics and leaves the timbre to the instrument and the room; a VLA patch fixes every control voltage, every probability and every knob, and leaves the sound to the host's graph. What the notes cannot do, the file does: the same patch with the same seed produces the same control log on any machine, frame for frame (§6), which no rack and no page of notes can promise, and a week of attenuation and offsets becomes numbers in labeled cells another artist can diff, fork and turn. The practice exists in neighboring forms (*exhibits*, §14): Csound has split the instrument from the score since 1986; VCV Rack and Pure Data patches are text files people trade; a Standard MIDI File is the output of a generative patch, where the VLA file is the patch. What VLA adds is the spreadsheet as the substrate, every value visible, every knob a cell, the previous frame a sheet, determinism by construction, and English through Frazaro; what it lacks today is the audio half, which is why the first Fragments sounds like a music box over a drone rather than like the track, and why the patch sheet is the version that matters to the artists the owner means.

*The golden patch.* Fragments is the golden patch of `modular.vla`, the owner's reading of 2026-10-08, so the dictionary a scoping will build on is written here before it starts. A module is a row of the Patch sheet: its knobs are the cells to the right of its output, its inputs are the references inside its formula, its output is the named cell. A cable is a reference. A mult is several formulas reading one name, free where a rack pays a module. A feedback cable, an output looped into its own input, is a `.last` reference, one frame late, which is the only way a loop is stable without a slew. A VCA, an attenuator, an offset and a CV mixer are arithmetic inside the formula and never rows. The cable list of a whole patch is a relation the house already prints, `reflect`'s `refers` rows, every cell against every cell it reads (*shelf*: oracle 8), so the patch sheet printed that way is the patch bay drawn as text:

```text
(refers "Patch!B6" "Patch!B3")        ; the cable from bar
(refers "Patch!B6" "Patch!B5")        ; the cable from dice
(refers "Patch!B6" "Patch.last!B6")   ; the feedback cable, a frame late
```

The distance between C.1 and the rack in the owner's screenshot of the performance is quantitative, not categorical. The notes name about forty-five control functions and about twenty-five audio ones, and the plumbing between them, the mults and attenuators and offsets, costs nothing in cells; so a faithful Fragments is on the order of seventy module rows and a hundred connections, five or six hundred lines in the layout above, of which the audio rows and their connections are the patch sheet's and not version 1's (*prediction*, 2026-10-08, for `CART.5`'s scoping to count). Software duplicates every module of that rack in kind, and several already exist in VCV Rack's library as their makers' own ports, Mutable Instruments' Marbles and Rings, Vult's filters, Instruō's modules and the chaotic Sloths (*exhibit*, §14); MIDI alone does not, since MIDI carries control and not audio, which is why the replay is MIDI-shaped and the sound is the graph's. The one categorical gap is the recordings, the rain, the harbor, the music box and the looped improvisation, which no patch synthesizes and a cartridge must carry as data (§12). And the render itself is beyond every substrate including the rack: three analog chaotic oscillators and probability on every trigger mean it never plays the piece the same way twice, where the cell version reproduces one performance exactly and forever; the file duplicates the patch, never the night. The oracle follows (*recommendation*): `modular.vla` is held by two goldens of Fragments in the house's shape, the expansion golden, the rows `fragments.vla` expands into, and the replay golden, the Audio sheet's log over a fixed number of frames under a fixed seed, so that a change to a macro that changes a row or a note is caught on every push; a new module enters the library with its row in C.5's table and its line in the goldens.
